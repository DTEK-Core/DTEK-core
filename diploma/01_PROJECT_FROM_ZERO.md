# 01. DTEK Core с абсолютного нуля

Для каждого понятия используем одну схему: простое значение, реализация в проекте, путь и смысл.

## Программа и веб-приложение

**Простыми словами:** программа — набор инструкций компьютеру. Веб-приложение открывается браузером, но данные и важные операции находятся на сервере.

**В DTEK Core:** браузер показывает объекты, риски и граф; сервер проверяет пользователя и работает с Supabase.

**Где посмотреть:** `app/`, `components/`, `lib/actions/`.

**Почему важно:** интерфейс нельзя считать границей безопасности.

## Frontend, backend, сервер и API

**Простыми словами:** frontend — видимая часть; backend — правила и работа с данными; сервер — компьютер/процесс, где backend выполняется; API — согласованный способ обмена запросами.

**В DTEK Core:** React/Next.js строят экран, Server Actions выполняют изменения, API route `app/api/reports/risks/route.ts` отдаёт CSV.

**Где посмотреть:** `components/shared/objects/`, `lib/actions/objects.ts`, `app/api/`.

**Почему важно:** секретный ключ допустим только на серверной стороне.

## База данных

**Простыми словами:** структурированное долговременное хранилище.

**В DTEK Core:** PostgreSQL хранит организации, профили, объекты, паспорта, риски, связи, историю и аудит.

**Где посмотреть:** `supabase/migrations/001_helper_functions.sql`–`017_security_events.sql`.

**Почему важно:** ограничения и RLS защищают данные даже при ошибке приложения.

## SaaS, B2B и multi-tenant

**Простыми словами:** SaaS — программа как онлайн-сервис; B2B — продукт для организаций; multi-tenant — одна платформа обслуживает несколько клиентов, но разделяет их данные.

**В DTEK Core:** каждая запись содержит `organization_id`, а RLS сравнивает его с организацией текущего пользователя.

**Где посмотреть:** миграции `003_organizations.sql`, `005_objects.sql`, функция `current_org_id()`.

**Почему важно:** утечка между организациями является критической угрозой.

## Аутентификация, авторизация и роль

**Простыми словами:** аутентификация отвечает «кто вы?», авторизация — «что вам можно?», роль группирует разрешения.

**В DTEK Core:** Supabase Auth создаёт сессию; роли `owner`, `analyst`, `admin`, `viewer` проверяются Server Actions и RLS.

**Где посмотреть:** `lib/actions/auth.ts`, `middleware.ts`, `docs/security/RBAC_MODEL.md`.

## Миграция БД

**Простыми словами:** пронумерованная инструкция изменения схемы, которую можно повторить в разных окружениях.

**В DTEK Core:** 17 последовательных SQL-файлов создают схему и hardening.

**Где посмотреть:** `supabase/migrations/`.

## Git, репозиторий и Sprint

**Простыми словами:** Git хранит историю изменений; репозиторий — папка проекта с этой историей; Sprint — ограниченный этап с целью и Definition of Done.

**В DTEK Core:** рабочая ветка `develop`; Sprint 11 закрыт, Sprint 12 реализован и ждёт ручной приёмки.

**Где посмотреть:** `tasks/SPRINT_*.md`, `CHANGELOG.md`, `git log`.

> Главное, что нужно запомнить: экран, сервер и БД — разные слои, а безопасность проверяется на каждом доверительном переходе.
