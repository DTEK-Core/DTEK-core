# 20. Процесс разработки

```text
идея → анализ → Roadmap → Sprint → задача → чтение кода
→ реализация → миграции при необходимости → тесты → исправления
→ документация → commit → push → ручная приёмка → закрытие Sprint
```

Product Owner определяет ценность и границу; архитектор сохраняет целостность; разработчик реализует; тестировщик ищет несоответствия; ИБ-специалист анализирует угрозы; AI-ассистент ускоряет анализ/код/документы; автор диплома принимает решения и способен их объяснить.

ИИ полезен для вариантов, поиска связей и рутинных изменений, но может уверенно ошибаться, смешивать план и факт, пропускать права или придумывать API. Поэтому результат проверяется кодом, миграциями, тестами, Git diff и ручным сценарием.

Фактические правила находятся в `AI_DEVELOPMENT_GUIDE.md`, `AGENTS.md`, ADR и текущем Sprint. Новый Sprint не начинается автоматически после подготовки документов.

> Главное, что нужно запомнить: личный вклад автора — постановка проблемы, выбор и понимание решений, проверка результата и ответственность, а не количество вручную набранных строк.

## Проверь себя

1. Кто принимает product boundary?
2. Почему документация обновляется до закрытия Sprint?
3. Как проверить предложение ИИ?
4. Что должен уметь автор диплома?
