# Учебная документация DTEK Core

Эта папка помогает автору не заучить описание проекта, а понять его: от базовых терминов до RLS, Trust Score и защиты диплома. Источник истины здесь — код, миграции и актуальные документы на 03.08.2026.

## Как читать

1. Начните с [карты обучения](00_PROJECT_LEARNING_MAP.md).
2. Если веб-разработка пока незнакома, прочитайте [проект с нуля](01_PROJECT_FROM_ZERO.md).
3. Затем изучите продукт: документы 02–06.
4. После этого переходите к технике: документы 07–22.
5. Для диплома используйте документы 23–25.
6. Для практики держите рядом [глоссарий](26_GLOSSARY.md), [навигацию по коду](27_CODE_NAVIGATION_GUIDE.md) и [план обучения](28_PRACTICAL_STUDY_PLAN.md).

## Статусы

- **Реализовано** — существует работающий UI и серверная/БД-логика.
- **Реализовано частично** — полезный сценарий работает, но есть зафиксированные ограничения.
- **Подготовлена архитектура** — решение описано, но runtime отсутствует.
- **Запланировано** — есть Roadmap/Sprint, реализации нет.
- **Не реализовано** — отсутствует и код, и готовый пользовательский сценарий.

## Важно перед защитой

Обязательно уметь своими словами объяснить границу продукта, tenant isolation, разницу RBAC и RLS, формулу Trust Score, create-only импорт и отличие source metadata от полноценного Evidence Layer.

> Главное, что нужно запомнить: DTEK Core уже является функциональным ручным и import-driven MVP, но ещё не является автоматизированной connector-платформой.
