## 1. Цель спринта

**Провести полное комплексное тестирование платформы DTEK Core** по результатам Sprint 05 (Trust Score Engine, Dashboard, Trust Graph, Configurator) и Sprint 06 (Security Hardening).

Цели:
- Подтвердить корректность всех 12 функциональных блоков
- Верифицировать безопасность: RLS, RBAC, Security Headers, Rate Limiting, Audit Log
- Зафиксировать найденные дефекты и устранить их
- Подготовить кодовую базу к Sprint 08 (UX-полировка и production-hardening)

| Параметр | Значение |
|---|---|

| Тип работ | QA, тестирование, bug fix, документирование |

**Что тестируется — Sprint 05 добавил:**
- Trust Score Engine (автоматический пересчёт, триггеры, история)
- Dashboard (KPI-карточки, Trust Ring организации, топ рисковых объектов, тренд)

**Что тестируется — Sprint 06 добавил:**
- RLS-hardening (16 миграция, deny-политики)
- RBAC в Server Actions (generic error messages, sanitised inputs)
- Zod v4 валидация всех мутирующих Server Actions
- Security Headers (X-Frame-Options, CSP, HSTS, Referrer-Policy, Permissions-Policy)
- Rate Limiting Middleware (`/join` 10 req/min, `/api/` 60 req/min, 413 payload guard)
- Система аудита (таблица `security_events`, fire-and-forget helper, UI в /settings)

**Принцип работы:** точечные исправления найденных замечаний, без рефакторинга рабочих частей.

## 6. Quality Gate — аудит безопасности

### S07-T003 — Безопасность

| Область | Проверка | Статус |
|---|---|---|
| **RLS** | Политика `profiles_select`: пользователь видит свой профиль и профили своей org | ⬜ |
| **RLS** | DENY-политики на `trust_factor_config`, `trust_passports`, `trust_score_history`, `invitations`, `object_risks`, `relations` блокируют write через user-клиент | ⬜ |
| **RBAC SA** | `updateOrganization` не принимает `orgId` от клиента | ⬜ |
| **RBAC SA** | Все SA возвращают generic error messages (нет утечки деталей ошибки) | ⬜ |
| **Zod** | Все мутирующие Server Actions: `createObject`, `updateObject`, `createRisk`, `updateRisk`, `sendInvitation`, `changeUserRole`, `blockUser`, `updateOrganization`, `saveWeights` — используют Zod-схемы | ⬜ |
| **Headers** | `X-Frame-Options: DENY` присутствует в каждом HTTP-ответе | ⬜ |
| **Headers** | `X-Content-Type-Options: nosniff` присутствует | ⬜ |
| **Headers** | `Content-Security-Policy` присутствует и содержит `frame-ancestors 'none'` | ⬜ |
| **Headers** | `Referrer-Policy: strict-origin-when-cross-origin` присутствует | ⬜ |
| **Headers** | `Permissions-Policy` присутствует (camera, mic, geo, payment = deny) | ⬜ |
| **Rate Limit** | `/join` → 429 после 10 запросов за 60 секунд | ⬜ |
| **Rate Limit** | Content-Length > 100KB → 413 | ⬜ |
| **Audit Log** | События записываются в `security_events` при: смене роли, блокировке, удалении, приглашении, принятии приглашения, отзыве приглашения, обновлении организации, изменении весов | ⬜ |
| **Audit Log** | Журнал аудита виден только owner/admin в /settings | ⬜ |

## 7. Тест-сценарии: 12 функциональных блоков

> **Условные обозначения:**
> - **P** = Позитивный сценарий (happy path)
> - **N** = Негативный сценарий (невалидные данные, граничные случаи)
> - **RBAC** = Проверка разграничения прав
> - **ERR** = Сценарий ошибки (сеть, сервер, unauthorized)
> - **UX** = Визуальные и интерфейсные проверки
> - **SEC** = Проверка безопасности

## 8. Чеклист безопасности Sprint 06

> Полная верификация всех мер безопасности, внедрённых в Sprint 06.

### RLS (Row Level Security)

- [ ] `profiles` — пользователь видит только свой профиль и профили своей организации
- [ ] `organizations` — пользователь видит только свою организацию
- [ ] `objects` — пользователь видит только объекты своей организации
- [ ] `trust_passports` — только чтение через user-клиент; запись только через admin/SA
- [ ] `trust_factor_config` — только чтение; запись только через admin/SA
- [ ] `trust_score_history` — только чтение; запись только через admin/SA
- [ ] `risks` — CRUD только для своей организации
- [ ] `invitations` — только чтение; update/delete только через admin/SA
- [ ] `relations` — CRUD только для своей организации (update через admin/SA)
- [ ] `security_events` — только чтение через SELECT; INSERT/UPDATE/DELETE via admin

### RBAC в Server Actions

- [ ] `updateOrganization` — не принимает `orgId` от клиента (берёт из профиля)
- [ ] `changeUserRole` — проверяет роль caller (только owner/admin)
- [ ] `blockUser` / `removeUser` — проверяет что нельзя заблокировать owner
- [ ] `sendInvitation` — роль `owner` в payload отклоняется
- [ ] `saveWeights` — только owner

### Zod-валидация

- [ ] `createObject` — все обязательные поля валидируются
- [ ] `updateObject` — поля валидируются; extra fields stripped
- [ ] `createRisk` — обязательные поля, тип категории из enum
- [ ] `sendInvitation` — email format, role enum без `owner`
- [ ] `changeUserRole` — role enum
- [ ] `updateOrganization` — min length для name
- [ ] `saveWeights` — числа в диапазоне, сумма = 100

### HTTP Security Headers

- [ ] `X-Frame-Options: DENY` — на всех маршрутах
- [ ] `X-Content-Type-Options: nosniff` — на всех маршрутах
- [ ] `Referrer-Policy: strict-origin-when-cross-origin`
- [ ] `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`
- [ ] `Content-Security-Policy` с `frame-ancestors 'none'`, `connect-src` для Supabase host

### Rate Limiting

- [ ] `/join` → 429 при > 10 запросов/60с с одного IP
- [ ] `/api/` → 429 при > 60 запросов/60с с одного IP
- [ ] Payload > 100KB → 413 (проверяется по `Content-Length`)
