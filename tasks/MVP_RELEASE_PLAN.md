## 1. О документе

Этот план разбивает 53 фичи DTEK Core MVP на 7 последовательных релизов (Release 0–6). Каждый релиз доставляет осмысленную, тестируемую ценность — либо для команды разработки, либо для конечного пользователя.

**Принципы разбивки:**
- Каждый релиз заканчивается конкретной наблюдаемой способностью пользователя — не просто набором закрытых задач
- Release 0 — единственный, который не несёт пользовательской ценности; он только технический
- Фичи группируются по смысловой связности, а не строго по Epic-границам
- Фичи с кросс-Epic зависимостями (F-026, F-027, F-031, F-033) включаются в тот релиз, в котором они достигают своей основной ценности

**Связанные документы:**
- `tasks/FEATURE_BACKLOG.md` — 53 фичи с приоритетами, размерами, зависимостями
- `tasks/EPIC_BACKLOG.md` — 11 Epic с критериями завершения
- `ARCHITECTURE_DECISIONS.md` — ADR-001–005

**Всего:** 13 фич · S×6, M×5, L×1

### Зачем нужно

Это первое, что видит реальный пользователь. Регистрация, организация и команда — «входной барьер» продукта. Если эти три шага работают плохо, пользователь уходит до того, как увидит ценность.

Онбординг-мастер (F-011) здесь критичен: он формирует базовую структуру организации за 5–10 минут и создаёт первое впечатление о платформе. Без RBAC (F-018) нельзя безопасно передавать продукт команде — любой участник получит доступ ко всему.

Инвесторам и первым пилотным клиентам этот релиз нужен уже сейчас: они должны видеть живой продукт с авторизацией, а не mockup.

### Ожидаемый результат

- Новый пользователь регистрируется по email, подтверждает адрес, создаёт организацию
- Мастер первичной настройки проводит через 5 шагов и создаёт базовую структуру
- Пользователь попадает на пустой Dashboard (данных ещё нет)
- Владелец приглашает коллег по email, те принимают приглашение с нужной ролью
- Заблокированный участник теряет доступ мгновенно
- Один аккаунт может управлять несколькими организациями

### Оценка

**10–14 рабочих дней** (Auth 3–5 + Organizations 3–4 + User Management 4–5)

## 5. Release 2 — Цифровая модель данных

> **Milestone:** Цифровая модель заполнена

### Что входит

| ID | Feature | Размер |
|---|---|---|
| F-019 | Objects List Screen | M |
| F-020 | Object CRUD | M |
| F-021 | Object Detail Screen | L |
| F-022 | Object Type System & Archive | S |
| F-023 | Object RBAC Enforcement | S |
| F-024 | Passport Screen Layout | M |
| F-025 | Trust Ring Component | S |
| F-026 | Factor Breakdown Section *(скелет)* | M |
| F-029 | Risk Registry Screen | M |
| F-030 | Risk CRUD | M |
| F-031 | Risk-Object Linking *(без триггера пересчёта)* | M |
| F-032 | Risk Status Flow | S |
| F-034 | SLA Tracking | S |

**Всего:** 13 фич · S×4, M×8, L×1

> **Примечание о скелетах:** F-026 (Factor Breakdown) строится как UI-оболочка. Trust Score объекта при создании устанавливается в базовое значение по критичности (Critical=65, High=70, Medium=75, Low=80) — без полного расчёта Engine. Автоматический триггерный пересчёт появится в Release 4.

### Зачем нужно

Это ядро продукта. Без объектов нет паспортов, без рисков нет смысла в Trust Score. Release 2 превращает платформу из «красивой авторизации» в инструмент, с которым аналитик начинает реальную работу.

Паспорт доверия (F-024–F-026) включается здесь — не в отдельном релизе — потому что он автоматически создаётся при добавлении объекта. Пользователь должен сразу видеть паспорт как центральный артефакт, даже если факторные оценки пока показывают начальные значения.

Risk-Object Linking (F-031) без триггера пересчёта означает, что привязка работает, но Trust Score не обновляется автоматически. Это сознательный компромисс: логика привязки и Engine разрабатываются в разных релизах.

### Ожидаемый результат

- Аналитик создаёт объекты всех типов с нужными атрибутами (IP, платформа, критичность, сегмент)
- При создании объекта автоматически появляется Trust Passport с начальным Trust Score
- Passport Screen открывается: Trust Ring, 6-факторная разбивка (начальные значения), реквизиты
- Аналитик регистрирует риски и привязывает их к объектам
- Риски видны на странице объекта и в реестре с фильтрами, поиском, SLA
- Trust Score в объекте показывает базовое значение по критичности, не автоматически пересчитанное
- Администратор ограничен в создании объектов (только инфраструктурные типы — сервер, сеть, рабочая станция)

### Оценка

**13–18 рабочих дней** (Objects 5–7 + Passport UI 2–3 + Risks 6–8)

## 6. Release 3 — Визуальная модель

> **Milestone:** Модель визуализирована

### Что входит

| ID | Feature | Размер |
|---|---|---|
| F-041 | Graph Library & Rendering Engine | L |
| F-042 | Node Styling & Layout | M |
| F-043 | Relation Management UI | M |
| F-044 | Node Detail Panel | M |
| F-045 | Graph Filters & Legend | S |

**Всего:** 5 фич · S×1, M×3, L×1

### Зачем нужно

Trust Graph — «wow-фактор» продукта. Это визуальная метафора «цифровой модели доверия», которой нет ни в одном традиционном инструменте безопасности: ни в SIEM, ни в сканере уязвимостей, ни в реестре активов.

Граф намеренно выносится в отдельный релиз — до Engine — по двум причинам:

1. **Демонстрационная ценность.** С объектами и рисками из Release 2, но без полного Trust Score, граф уже показывает живую инфраструктурную карту с цветовой индикацией начальных уровней доверия. Этого достаточно для демонстрации концепции инвесторам.

2. **Техническая независимость.** F-041–F-045 не зависят от Trust Score Engine. Узлы берут данные из таблицы `objects`, рёбра — из `relations`. Граф можно разрабатывать параллельно с Engine.

### Ожидаемый результат

- Аналитик открывает экран Trust Graph: все активные объекты отображаются как узлы
- Цвет узла соответствует уровню доверия объекта, размер — критичности
- Аналитик создаёт связи между объектами (6 типов: использует/зависит от/подключён к/управляется/владеет/взаимодействует)
- Клик по узлу открывает боковую панель с Trust Ring, метриками, кнопками перехода в паспорт и детали объекта
- Граф поддерживает zoom, pan, drag-n-drop
- Фильтр по типу объекта выделяет нужные узлы и приглушает остальные

### Оценка

**5–7 рабочих дней**

## 7. Release 4 — Движок доверия

> **Milestone:** Модель ожила

### Что входит

| ID | Feature | Размер |
|---|---|---|
| F-036 | Score Calculation Engine | L |
| F-037 | Recalculation Triggers | M |
| F-038 | Score History Storage | S |
| F-039 | Org Trust Index | S |
| F-040 | Score Trend Chart | M |
| F-027 | Change History Section *(теперь полная)* | S |
| F-033 | Risk Drawer *(теперь полный с impact)* | M |

**Всего:** 7 фич · S×3, M×3, L×1

> **Примечание об активации скелетов:** После этого релиза F-026 (Factor Breakdown) начинает показывать реальные вычисленные значения, а не начальные базовые. F-027 (Change History) наполняется реальными записями. F-031 (Risk-Object Linking) получает автоматический триггер пересчёта.

### Зачем нужно

Это переломный релиз. До него платформа — это структурированный реестр данных. После него — живая модель доверия: Trust Score меняется при каждом действии аналитика.

F-036 реализует формулу из `Trust_Score_Model_v2.md` в виде Supabase Edge Function: 6 факторов, штрафы за риски по категориям, бонус за полноту паспорта. F-037 создаёт триггеры, которые автоматически запускают пересчёт при любом изменении объекта, риска или связи.

Risk Drawer (F-033) становится полезным именно здесь: только после Engine он может показать «устранение этого риска повысит Trust Score на ~N пунктов» — конкретную рекомендацию к действию.

### Ожидаемый результат

- Trust Score объекта пересчитывается автоматически при: добавлении/изменении/закрытии риска, изменении критичности объекта, привязке/отвязке риска
- Факторная разбивка в паспорте показывает реальные вычисленные значения (Уязвимости, Конфигурация, Доступы, Сегментация, Соответствие, Инциденты)
- История изменений Trust Score наполняется: каждое изменение записывается с причиной и факторным снимком
- Организационный индекс доверия (взвешенное среднее по критичности объектов) обновляется при каждом пересчёте
- График тренда Trust Score доступен на экране деталей объекта
- Risk Drawer показывает расчётное влияние устранения риска на Trust Score объекта

### Оценка

**7–9 рабочих дней** (Engine 4–5 + triggers/history 1–2 + chart/drawer 2)

## 8. Release 5 — MVP Complete

> **Milestone:** MVP готов к демонстрации

### Что входит

| ID | Feature | Размер |
|---|---|---|
| F-046 | Dashboard Layout & KPI Cards | M |
| F-047 | Org Trust Ring & Trend Chart | M |
| F-048 | Top Risky Objects | S |
| F-049 | Event Feed with Realtime | M |
| F-050 | Trust Distribution Chart | S |
| F-051 | Weights Editor Screen | M |
| F-052 | Weights Validation & Save | S |
| F-053 | Mass Recalculation & Notification | M |

**Всего:** 8 фич · S×2, M×5, L×0

### Зачем нужно

Dashboard — первый экран, который видит пользователь после входа. Он отвечает на вопрос «что сейчас происходит с моей организацией» за 10 секунд. Без Dashboard данные платформы разрозненны: аналитик должен обходить каждый объект вручную, чтобы понять общую картину.

Конфигуратор (F-051–F-053) завершает ценностное предложение: DTEK Core не «ещё один инструмент с жёсткими параметрами», а адаптируемая модель. Банк, энергетическая компания и ритейлер могут расставить акценты под свою отрасль — изменив веса факторов Trust Score.

После этого релиза все 51 P1/P2-фича реализованы. MVP готов к первым реальным клиентам.

### Ожидаемый результат

- Dashboard открывается с Trust Ring организации, KPI-карточками, трендом за 30/90/365 дней
- Лента событий обновляется в реальном времени (Supabase Realtime) — новые риски, изменения Score
- Топ-5 объектов с наименьшим Trust Score кликабельны: переход в паспорт за один клик
- Распределение по уровням доверия кликабельно: открывает отфильтрованный список объектов
- Аналитик открывает Конфигуратор, меняет веса факторов (например, повышает вес «Соответствие» для регулируемой отрасли), получает пересчёт всех объектов организации и уведомление о завершении
- **MVP полностью готов к демонстрации клиентам и инвесторам**

### Оценка

**6–8 рабочих дней** (Dashboard 3–4 + Configurator 3–4)

> **Milestone:** Продукт готов к первым внешним демонстрациям и ручным пилотам

### Что входит

| ID | Feature | Размер |
|---|---|---|
| F-028 | PDF Export | L |
| F-035 | CSV Export | S |
| M-001 | Demo Seed Data | M |
| M-002 | CSV Import Objects | M |
| M-003 | CSV Import Risks | M |
| M-004 | Executive Report | M |
| M-005 | Trust Score Explainability | M |
| M-006 | Risk Impact Hint | S |
| M-007 | Pilot Runbook | S |

**Всего:** 9 фич · S×3, M×5, L×1

### Зачем нужно

После Sprint 08 главный риск проекта — не отсутствие новых экранов, а недостаточная готовность к реальным данным, отчётности и пилотам.

Экспорт остаётся важным, но теперь он является частью более широкого Market MVP: продукт должен быть можно показать CISO, наполнить данными и выдать управленческий результат.

PDF Export (F-028) и CSV Export (F-035) становятся обязательными для пилотного сценария, потому что без отчётов продукт сложно использовать в аудитах и презентациях руководству.

### Ожидаемый результат

- Аналитик на экране паспорта нажимает «Экспорт PDF» и получает файл с заголовком, Trust Ring, факторной разбивкой, списком рисков, реквизитами, датой генерации и логотипом платформы
- Аналитик в реестре рисков нажимает «Экспорт CSV» и получает файл со всеми полями отфильтрованных рисков
- В продукте есть демо-организация с реалистичными объектами, рисками и связями
- CISO получает executive report по организации
- Пользователь понимает причины Trust Score и ожидаемый эффект закрытия риска
- Команда имеет runbook для первых пилотов

### Оценка

**8–15 рабочих дней**
