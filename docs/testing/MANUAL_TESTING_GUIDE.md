# MANUAL_TESTING_GUIDE.md — DTEK Core

> Подробная пошаговая инструкция для ручного тестирования всей платформы.  
> Пройдите все шаги по порядку. При обнаружении проблемы — запишите скриншот
> и используйте шаблон `BUG_REPORT_TEMPLATE.md`.

---

## Подготовка

1. Убедитесь что локальный сервер запущен:
   ```bash
   npm run dev
   ```
   Откройте http://localhost:3000 в браузере Chrome или Safari.

2. Откройте DevTools (F12 или Cmd+Option+I) и перейдите на вкладку **Console**.
   Убедитесь что Console пуста — в ней не должно быть красных ошибок.

3. Держите DevTools открытым на вкладке **Network** чтобы видеть запросы.

## Шаг 1: Лендинг

**URL:** http://localhost:3000

**Что проверять:**
- [ ] Страница открывается без белого экрана и без ошибок в Console
- [ ] Фон тёмный (`#07090d`), логотип DTEKCore виден в шапке
- [ ] Шапка содержит: логотип, навигационные ссылки, кнопки «Войти» и «Запросить доступ»
- [ ] Секция Hero: заголовок «Цифровая модель доверия вашей организации», Trust Graph справа
- [ ] Секция Features: 4 карточки с иконками (паспорт, оценка, граф, конфигуратор)
- [ ] При прокрутке страницы шапка становится полупрозрачной с тонкой рамкой снизу
- [ ] Секция статистики: 4 числа (1248, 6, 5, 74) с анимацией CountUp при прокрутке к ним
- [ ] Кнопка «Войти» в шапке → переходит на /login
- [ ] Кнопка «Запросить доступ» → переходит на /register

**Если уже залогинены:** Страница должна автоматически редиректить на /dashboard.  
Для тестирования лендинга откройте окно инкогнито.

## Шаг 2: Регистрация

**URL:** http://localhost:3000/register

**Что проверять:**
- [ ] Двухпанельный layout: левая панель с Trust Ring и описанием, правая — форма
- [ ] Переключатель «Вход / Регистрация» в верхней части формы
- [ ] Форма содержит поля: Имя, Фамилия, Рабочий email, Пароль
- [ ] Нажать «Создать аккаунт» с пустыми полями → поля выделяются (HTML5 validation)

**Тест (создание аккаунта):**
1. Заполните все поля:
   - Имя: `Тест`
   - Фамилия: `Пользователь`
   - Email: `test-YYYYMMDD@example.com` (уникальный)
   - Пароль: `TestPass123!`
2. Нажмите «Создать аккаунт»
3. **Ожидаем:** Перенаправление на `/onboarding/create`

## Шаг 6: Объекты — Список

**URL:** /objects (нажать «Объекты» в сайдбаре)

**Что проверять:**
- [ ] Заголовок «Объекты» с подзаголовком «N объектов в цифровой модели»
- [ ] Кнопки в шапке: «Экспорт» (неактивная), «Добавить объект» (активная)
- [ ] Поле поиска с placeholder «Поиск по имени или ID…»
- [ ] Выпадающие фильтры «Тип» и «Уровень»
- [ ] Переключатель Таблица / Карточки
- [ ] Таблица с колонками: Объект, Тип, Сегмент, Критичность, Риски, Доверие, Обновлён

**Тест поиска:**
1. Введите часть слова в поле поиска → таблица фильтруется в реальном времени
2. Очистите поиск — список возвращается к полному

**Тест фильтра «Тип»:**
1. Нажмите «Тип» → откроется выпадающий список
2. Выберите любой тип (например, «Сервер»)
3. Фильтр должен подсветиться (teal-цвет), таблица — отфильтроваться

**Тест переключения вида:**
1. Нажмите кнопку «▦» (карточки) — должны появиться карточки-объекты
2. Нажмите «☰» (таблица) — возврат к таблице

## Шаг 7: Создание объекта

На странице /objects нажмите «Добавить объект».

**Что проверять:**
- [ ] Открывается диалоговое окно с полями формы
- [ ] Поля: Название (обязательное), Тип, Критичность, Сегмент, IP/URL, Описание

**Тест:**
1. Оставьте «Название» пустым → нажмите «Создать объект» → ошибка валидации
2. Заполните:
   - Название: `Тестовый сервер`
   - Тип: `server`
   - Критичность: `medium`
3. Нажмите «Создать объект»
4. **Ожидаем:** Диалог закрывается, объект появляется в таблице

---

## Шаг 8: Детали объекта

Нажмите на строку любого объекта в таблице.

**URL:** /objects/[uuid]

**Что проверять:**
- [ ] Заголовок: тип-иконка + название объекта + бейдж критичности
- [ ] Trust Ring (кольцо с числом 0–100) виден
- [ ] Строка мета-данных: ID, тип, сегмент
- [ ] Вкладки: Обзор, Факторы доверия, Риски, Связи, История
- [ ] Кнопка «Паспорт доверия» (ссылка на /objects/[id]/passport)

**Тест вкладок:**
1. Нажмите «Факторы доверия» — 6 факторов с метрами (Уязвимости, Конфигурация, и т.д.)
2. Нажмите «Риски» — таблица рисков объекта или сообщение «Рисков нет»
3. Нажмите «Связи» — список связанных объектов
4. Нажмите «История» — временная шкала событий
5. Нажмите «Обзор» — возврат на обзор

## Шаг 9: Trust Passport

На странице деталей объекта нажмите «Паспорт доверия».

**URL:** /objects/[uuid]/passport

**Что проверять:**
- [ ] Хлебные крошки: «Объекты > [Название] > Паспорт доверия»
- [ ] Trust Ring большой (96px) с оценкой и меткой уровня
- [ ] Секция «Факторы доверия»: 6 строк с весами (%), значением и метром
- [ ] Секция «Реестр рисков объекта»: таблица рисков или «Рисков нет»
- [ ] Секция «Связанные объекты»: список или «Связей нет»
- [ ] Кнопка «← Объект» возвращает на страницу деталей

На странице /objects нажмите иконку карандаша (✎) справа на строке объекта.

**Что проверять:**
- [ ] Открывается диалог редактирования с заполненными полями
- [ ] Измените название на «Тестовый сервер v2», нажмите «Сохранить»
- [ ] Обновлённое название отображается в таблице

## Шаг 11: Удаление объекта

1. Откройте форму редактирования объекта «Тестовый сервер v2»
2. Нажмите кнопку «Удалить» (обычно красная/ghost)
3. Появится диалог подтверждения — нажмите «Удалить объект»
4. **Ожидаем:** Объект исчезает из таблицы, диалог закрывается

---

## Шаг 12: Реестр рисков — Список

**URL:** /risks (нажать «Реестр рисков» в сайдбаре)

**Что проверять:**
- [ ] 4 карточки-счётчика в верхней части: Критические (красный), Высокие (оранжевый), Средние (жёлтый), Низкие (голубой)
- [ ] Поле поиска и выпадающий фильтр «Статус»
- [ ] Таблица: Риск, Объект, Категория, Статус, SLA, Оценка (CVSS)
- [ ] Если рисков нет — пустое состояние с иконкой щита

**Тест карточек-фильтров:**
1. Нажмите карточку «Критические» → таблица показывает только критические, карточка подсвечена
2. Нажмите карточку повторно → фильтр снимается

**Тест фильтра по статусу:**
1. Нажмите выпадающий «Статус» → выберите «Открыт»
2. Таблица показывает только открытые риски

## Шаг 13: Создание риска

На /risks нажмите «Зарегистрировать риск».

**Тест:**
1. Название: `Тестовая уязвимость TLS`
2. Категория: `Уязвимость`
3. Серьёзность: `Высокий`
4. CVSS Score: `7.8`
5. SLA (дней): `30`
6. Нажмите «Создать риск»
7. **Ожидаем:** Риск появляется в таблице с правильной цветовой меткой серьёзности

---

## Шаг 14: Risk Drawer

Нажмите на строку только что созданного риска.

**Что проверять:**
- [ ] Справа открывается панель Risk Drawer
- [ ] Шапка drawer: тег серьёзности (ВЫСОКИЙ), заголовок риска, ID
- [ ] Секция оценки: число CVSS (7.8) крупным шрифтом, метр заполненности
- [ ] Сетка мета-данных: Объект, Категория, Статус, Владелец, Возраст, SLA
- [ ] Секция «Влияние на доверие»
- [ ] Секция «Рекомендуемые действия»: 3 шага (01, 02, 03)
- [ ] Подвал с кнопками действий

**Тест жизненного цикла:**
1. В drawer нажмите «Взять в работу» → статус меняется на «В работе»
2. Снова откройте drawer (или обновите страницу и кликните на риск)
3. Нажмите «Устранить» → статус меняется на «Устранён»
4. В resolved-состоянии появляется кнопка «Открыть повторно»

**Закрытие drawer:**
- Нажмите X в правом верхнем углу — drawer закрывается
- Кликните на оверлей слева от drawer — drawer закрывается

---

## Шаг 15: Привязка риска к объекту

1. Создайте риск БЕЗ привязки к объекту
2. Откройте его Risk Drawer
3. В секции «Объект» значение «—»
4. Ниже видна секция «Привязать к объекту» с кнопкой «Привязать к объекту»
5. Нажмите «Привязать к объекту»
6. Появится выпадающий список — выберите объект
7. Нажмите «Привязать»
8. **Ожидаем:** В мета-данных drawer и в таблице рисков появляется название объекта

---

## Шаг 16: Редактирование и удаление риска

1. Найдите созданный риск в таблице, нажмите иконку редактирования ✎
2. Измените название, нажмите «Сохранить» → изменения отразились
3. Откройте форму снова, нажмите «Удалить» → подтвердите
4. **Ожидаем:** Риск удалён из таблицы

## Шаг 17: Пользователи

**URL:** /users (нажать «Пользователи» в сайдбаре)

> Страница доступна только для ролей **owner** и **admin**.  
> Если залогинены как viewer/analyst — произойдёт redirect на /dashboard.
> В текущем MVP новые приглашения создаёт только **owner**; admin может видеть пользователей и управлять не-owner участниками.

**Что проверять:**
- [ ] Таблица участников: имя + email, роль, статус, дата активности
- [ ] Кнопка «Пригласить»

**Тест приглашения:**
Выполняйте этот тест под ролью **owner**.

1. Нажмите «Пригласить»
2. Введите email: `invite-test@example.com`
3. Выберите роль: `analyst`
4. Нажмите «Создать ссылку»
5. **Ожидаем:** Строка с email появляется в таблице со статусом «Приглашён»
