# RBAC_TESTING_GUIDE.md — DTEK Core

> Пошаговое руководство по ручной проверке разграничения прав доступа (RBAC).
> Используйте этот документ для верификации работы ролей:
> `owner`, `admin`, `analyst`, `viewer`.

## Матрица прав (краткая)

| Действие | owner | analyst | admin | viewer |
|---|:---:|:---:|:---:|:---:|
| Создать объект | ✅ | ✅ | ✅¹ | ❌ |
| Редактировать объект | ✅ | ✅ | ✅ | ❌ |
| Архивировать объект | ✅ | ❌ | ❌ | ❌ |
| Создать риск | ✅ | ✅ | ❌ | ❌ |
| Изменить статус риска | ✅ | ✅ | ❌ | ❌ |
| Удалить риск | ✅ | ✅ | ❌ | ❌ |
| Создать связь в графе | ✅ | ✅ | ✅ | ❌ |
| Удалить связь в графе | ✅ | ✅ | ✅ | ❌ |
| Пригласить пользователя | ✅ | ❌ | ✅ | ❌ |
| Изменить роль пользователя | ✅ | ❌ | ✅² | ❌ |
| Заблокировать пользователя | ✅ | ❌ | ✅² | ❌ |
| Удалить пользователя | ✅ | ❌ | ✅² | ❌ |
| Редактировать данные организации | ✅ | ❌ | ❌ | ❌ |
| Изменить веса конфигуратора | ✅ | ✅ | ❌ | ❌ |
| Просматривать журнал аудита | ✅ | ❌ | ✅ | ❌ |

> ¹ Admin создаёт только инфраструктурные объекты: server, workstation, laptop, network, ot  
> ² Admin управляет только пользователями с ролью analyst, viewer; не может изменить роль owner

## Часть 1 — Создание тестовых аккаунтов

### Шаг 1.1 — Тестовая организация

Используйте уже созданную тестовую организацию. Войдите как **owner**.

### Шаг 1.2 — Пригласить тестовых пользователей

Перейдите в `/users` → нажмите «Пригласить» четыре раза:

| Email | Роль | Примечание |
|---|---|---|
| `test-analyst@example.com` | analyst | Аналитик ИБ |
| `test-admin@example.com` | admin | Администратор |
| `test-viewer@example.com` | viewer | Наблюдатель |
| (owner уже есть) | owner | Ваш основной аккаунт |

Для каждого приглашения нажмите «Пригласить» → скопируйте ссылку вручную из таблицы Supabase или откройте email.

> **Быстрый способ создать пользователей без email:**
> 1. Откройте [Supabase Dashboard](https://supabase.com/dashboard) → Authentication → Users
> 2. Создайте пользователей с паролем через «Add user»: `test-analyst`, `test-admin`, `test-viewer`
> 3. Отправьте приглашения на их email из платформы → примите приглашения в соответствующих браузерах

### Шаг 1.3 — Принять приглашения

Для каждого тестового пользователя откройте **отдельный браузер** (см. ниже) и примите приглашение.

## Часть 2 — Как войти под разными ролями одновременно

Для RBAC-тестирования нужно одновременно работать от лица нескольких пользователей.

### Вариант 1: Разные браузеры (рекомендуется)

Используйте несколько браузеров на одном устройстве:

| Роль | Браузер |
|---|---|
| owner | Safari |
| analyst | Chrome |
| admin | Firefox |
| viewer | Chrome (режим инкогнито) |

Каждый браузер хранит сессию независимо.

### Вариант 2: Разные профили Chrome

1. В Chrome → нажмите иконку аккаунта в правом верхнем углу
2. «Добавить профиль» → создайте 4 профиля
3. В каждом профиле войдите под разной ролью

### Вариант 3: Режим инкогнито + обычный режим

- Обычный браузер: owner
- Cmd+Shift+N (Chrome/Safari): analyst
- Открыть ещё одно инкогнито невозможно в одном браузере → используйте Firefox

### Вариант 4: Два устройства

- MacBook: owner + analyst
- iPhone: admin или viewer

## Часть 3 — Проверка роли owner

Войдите как **owner** в Safari (или ваш основной браузер).

### Что должно работать:

**Пользователи (/users):**
- [ ] Видит список всех участников организации
- [ ] Может отправить приглашение на любую роль (кроме owner)
- [ ] Может изменить роль любого пользователя (кроме owner → нельзя изменить owner)
- [ ] Может заблокировать/разблокировать/удалить любого пользователя (кроме себя)

**Объекты (/objects):**
- [ ] Может создавать объекты любого типа
- [ ] Может архивировать объекты

**Риски (/risks):**
- [ ] Может создавать, изменять, удалять риски

**Конфигуратор (/configurator):**
- [ ] Видит кнопки «Сохранить и пересчитать» и «Сбросить по умолчанию»
- [ ] Может сохранять веса

**Настройки (/settings):**
- [ ] Видит вкладку «Журнал аудита»
- [ ] Может редактировать данные организации

## Часть 4 — Проверка роли analyst

Войдите как **analyst** в Chrome.

### Что должно работать:

**Объекты:**
- [ ] Может создавать объекты любого типа
- [ ] Может редактировать объекты
- [ ] **НЕ** может архивировать объекты

**Риски:**
- [ ] Может создавать, изменять, удалять риски

**Trust Graph:**
- [ ] Может создавать и удалять связи

**Конфигуратор:**
- [ ] Видит кнопки сохранения (редактирование разрешено!)
- [ ] Может сохранять веса факторов

### Что должно быть недоступно:

- [ ] В /users: нет кнопок «Пригласить», «Заблокировать», «Изменить роль»
- [ ] В /settings → Организация: поля readonly, кнопки сохранения нет
- [ ] В /settings: нет вкладки «Журнал аудита»

## Часть 5 — Проверка роли admin

Войдите как **admin** в Firefox.

### Что должно работать:

**Пользователи (/users):**
- [ ] Может пригласить пользователя с ролью analyst или viewer
- [ ] Может изменить роль analyst/viewer
- [ ] Может заблокировать/удалить analyst/viewer
- [ ] **НЕ** может изменить роль owner

**Объекты:**
- [ ] Может создавать **только инфраструктурные** типы: server, workstation, laptop, network, ot
- [ ] При попытке создать объект другого типа — ошибка доступа

**Настройки:**
- [ ] Видит вкладку «Журнал аудита»

### Что должно быть недоступно:

- [ ] Конфигуратор: поля readonly, кнопок сохранения нет
- [ ] Организация в /settings: поля readonly
- [ ] Создание рисков: ошибка «Только владелец или аналитик»

## Часть 6 — Проверка роли viewer

Войдите как **viewer** в режиме инкогнито.

### Что должно работать:

- [ ] Просмотр списка объектов (/objects)
- [ ] Просмотр деталей объекта (/objects/[id])
- [ ] Просмотр паспорта доверия (/objects/[id]/passport)
- [ ] Просмотр Trust Graph (/graph) — только просмотр, без изменений
- [ ] Просмотр реестра рисков (/risks) — только просмотр
- [ ] Просмотр Dashboard (/dashboard)

### Что должно быть недоступно:

- [ ] В /objects: кнопка «Добавить объект» отсутствует
- [ ] В /risks: кнопки «Добавить риск», «Изменить статус», «Удалить» отсутствуют
- [ ] В /graph: кнопка «Добавить связь» отсутствует в боковой панели
- [ ] В /users: кнопок управления пользователями нет
- [ ] В /configurator: поля readonly, кнопок сохранения нет
- [ ] В /settings: нет вкладки «Журнал аудита», нет редактирования организации

## Часть 7 — Тест попытки обхода через UI

Эти тесты проверяют, что сервер защищён, даже если обойти UI.

### Тест 7.1 — Analyst не может изменить роль через DevTools

1. Войдите как analyst в Chrome
2. Откройте DevTools → вкладку «Console»
3. Выполните:
   ```javascript
   // Попытка вызвать SA напрямую — невозможна из браузера
   // Вместо этого попробуйте через форму с модифицированным request
   ```
4. На практике: Next.js Server Actions вызываются через POST к специальному endpoint
5. **Проверка**: В /users нет UI для изменения ролей от имени analyst — кнопки скрыты на клиенте, SA на сервере также проверяет роль

**Ожидаемый результат:** Отсутствие кнопок в UI + SA вернёт `{ error: 'Нет прав...' }` если запрос всё же придёт

### Тест 7.2 — Viewer не видит данные другой организации

Предусловие: существует ≥ 2 организации в базе данных.

1. Войдите как viewer в org A
2. Попробуйте вручную изменить URL: `/objects?org=<id-org-B>`
3. **Ожидаемый результат:** Либо пустой список (RLS фильтрует), либо объекты только своей организации

## Советы и частые вопросы

**Q: Как быстро сменить роль пользователя для тестирования?**

A: В /users найдите пользователя → нажмите «Изменить роль» (только для owner/admin).

**Q: Как убедиться что вошли правильным пользователем?**

A: Перейдите в /settings → вкладка «Профиль». Там отображается email и роль текущего пользователя.

**Q: RLS — что это и как проверить?**

A: RLS (Row Level Security) — политики Supabase, которые фильтруют данные на уровне базы данных. Даже если клиент попытается запросить чужие данные напрямую через Supabase JS client, RLS вернёт пустой результат. Проверить можно в DevTools → Network: Supabase запросы возвращают только данные своей организации.

**Q: В одном браузере нельзя открыть два инкогнито окна — что делать?**

A: Safari: файл → «Новое частное окно» можно открыть несколько раз. В Chrome можно открыть только одно инкогнито окно за сессию. Используйте профили Chrome или другие браузеры.
