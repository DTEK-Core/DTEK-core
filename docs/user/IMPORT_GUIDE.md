# DTEK Core — Импорт объектов и рисков

`Версия: 1.2`
`Дата: 23.08.2026`
`Актуально для: Sprint 11 import runtime + Sprint 15 connector decision`

---

## Назначение

Импорт CSV/XLSX позволяет быстро наполнить DTEK Core исходными данными организации без ручного создания каждой записи.

После Sprint 15 import остаётся основным рабочим evidence onboarding path.
Connector Foundation специфицирован, но первый connector, Evidence Layer
runtime и Discovery Inbox не реализованы до появления pilot admission evidence.

В текущем MVP можно импортировать:

- объекты инфраструктуры и информационные активы;
- риски;
- одну связь импортируемого риска с существующим объектом;
- source metadata, описывающие происхождение данных.

Импорт работает в два этапа: сначала платформа проверяет файл и показывает preview, затем пользователь явно подтверждает создание валидных строк.

## Доступ По Ролям

| Операция | Владелец | Аналитик ИБ | Администратор | Наблюдатель |
|---|:---:|:---:|:---:|:---:|
| Импорт объектов | ✅ | ✅ | Ограниченно | ❌ |
| Импорт рисков | ✅ | ✅ | ❌ | ❌ |
| Просмотр import events в журнале аудита | ✅ | ❌ | ✅ | ❌ |

Администратор может импортировать только инфраструктурные типы объектов:

- `server`;
- `workstation`;
- `laptop`;
- `network`;
- `ot`.

Попытка администратора импортировать приложение, базу данных, сервис, identity, policy или другой неинфраструктурный объект будет показана как validation error.

## Поддерживаемые Файлы

| Параметр | Ограничение |
|---|---|
| Формат | `.csv` или `.xlsx` |
| CSV encoding | UTF-8, UTF-8 BOM допускается |
| CSV delimiter | comma `,`, semicolon `;` или tab |
| XLSX | Используется только первый лист |
| Заголовки | Первая строка файла |
| Максимальный размер | 5 МБ |
| Максимум строк данных | 500 |
| Максимум колонок | 40 |
| Максимальная длина одной ячейки | 10 000 символов |

Пустые строки игнорируются. Заголовки нормализуются: BOM и регистр не учитываются, пробелы и дефисы преобразуются в `_`. Поддерживаются quoted values и многострочные значения внутри кавычек.

## Шаблоны

В каждом диалоге импорта доступна команда **Шаблон CSV**.

Прямые ссылки:

- [шаблон объектов](../../public/templates/dtek-core-objects-import-template.csv);
- [шаблон рисков](../../public/templates/dtek-core-risks-import-template.csv).

Рекомендуемый порядок:

1. Скачайте соответствующий шаблон.
2. Сохраните строку заголовков без изменений.
3. Замените пример своими данными или добавьте новые строки.
4. Сохраните файл как UTF-8 CSV либо XLSX.
5. Не добавляйте формулы, макросы и скрытые листы с ожидаемыми данными импорта.

Если файл объектов загружен в импорт рисков или наоборот, DTEK Core остановит preview, объяснит ошибку выбора и предложит перейти в правильный раздел.

### Совместимость С Risk CSV Export

CSV, скачанный кнопкой **CSV** из Risk Registry, можно повторно загрузить в **Импорт рисков**.

Платформа автоматически сопоставляет:

- `Название` → `title`;
- `Категория key` → `category`;
- `Критичность key` → `severity`;
- `Статус key` → `status`;
- `Вероятность` → `probability`;
- `CVSS` → `cvss_score`;
- `Linked objects` → `linked_object_name`;
- `Source` и `Updated at` → source context.

Технические key-поля имеют приоритет над локализованными display-полями. Служебные Risk ID, Owner, Author, internal linked IDs и Evidence note безопасно игнорируются и показываются одной информационной записью.

Если risk export содержит несколько связанных объектов, Sprint 11 автоматически использует первый и показывает informational message. Остальные связи можно добавить вручную после импорта.

Object CSV export в текущем MVP отсутствует: кнопка **Экспорт** на `/objects` пока отключена. Для объектов используйте шаблон или готовые test fixtures.

## Source Metadata

Source metadata объясняют, откуда получены импортируемые данные.

Перед выбором файла в диалоге можно указать общие значения:

| Поле | Назначение | Default |
|---|---|---|
| Название источника | Человекочитаемое имя системы или выгрузки | Имя файла |
| Тип | Класс источника | `manual_csv` |
| Уверенность | Насколько данным можно доверять | `medium` |
| Дата сбора | Когда данные были получены | Не задана |
| Комментарий | Контекст импорта | Не задан |

Поддерживаемые `source_type`:

| Значение | Пример |
|---|---|
| `manual_csv` | Ручная инвентаризация |
| `asset_inventory` | CMDB или ITAM export |
| `vulnerability_export` | MaxPatrol VM или другой VM-сканер |
| `monitoring_export` | Zabbix или monitoring export |
| `directory_export` | AD, LDAP, FreeIPA |
| `security_tool_export` | Kaspersky, Wazuh, EDR/XDR-like tool |
| `network_export` | Firewall, NAC, сетевое оборудование |
| `other` | Другой источник |

Поддерживаемые значения `confidence`: `high`, `medium`, `low`.

Файл может содержать построчные колонки `source_name`, `source_type`, `source_record_id`, `source_collected_at`, `confidence` и `import_note`. Непустое значение строки имеет приоритет над общим значением из диалога. `external_id` используется как alias для `source_record_id`, если отдельный `source_record_id` не задан.

В Sprint 11 source context временно сохраняется в блоке `[Import Source]` внутри описания объекта или риска. Полноценные Evidence Layer tables относятся к следующим этапам Roadmap.

## Импорт Объектов

### Обязательные Колонки

| Колонка | Тип | Описание |
|---|---|---|
| `name` | string, 1–200 | Название объекта |
| `type` | enum | Тип объекта |

### Опциональные Колонки

| Колонка | Использование |
|---|---|
| `criticality` | `low`, `medium`, `high`, `critical`; default `medium` |
| `description` | Описание объекта, максимум 5000 символов вместе с source block |
| `ip_address` | IPv4, IPv6 или другое поддерживаемое адресное значение, максимум 45 символов |
| `os_platform` | ОС или платформа, максимум 200 символов |
| `segment` | Сегмент сети, максимум 200 символов |
| `exposure` | `internal`, `external`, `isolated` |
| `external_id` | Alias для `source_record_id` |
| `owner_email` | Проверяется, но в Sprint 11 не назначает владельца автоматически |
| Source columns | Поля из раздела Source Metadata |

### Типы Объектов

`server`, `workstation`, `laptop`, `network`, `app`, `database`, `service`, `identity`, `ot`, `policy`, `other`.

Поддерживаются распространённые алиасы, например `сервер`, `srv`, `host`, `db`, `application`, `firewall`, `ноутбук`, `учётная запись`. Канонические английские значения из шаблона остаются предпочтительным вариантом.

### Пример

```csv
name,type,criticality,ip_address,os_platform,segment,exposure
srv-db-01,server,critical,10.10.1.15,Astra Linux,prod-db,internal
```

После создания объекта платформа создаёт Trust Passport и назначает начальный Trust Score по текущей модели критичности.

## Импорт Рисков

### Обязательные Колонки

| Колонка | Тип | Описание |
|---|---|---|
| `title` | string, 1–500 | Название риска |
| `severity` | enum | `low`, `medium`, `high`, `critical` |

### Опциональные Колонки

| Колонка | Использование |
|---|---|
| `description` | Описание риска, максимум 5000 символов вместе с source block |
| `category` | Категория риска; default `other` |
| `status` | `open`, `in_progress`, `mitigated`, `accepted`, `closed`; default `open` |
| `probability` | `low`, `medium`, `high` |
| `cvss_score` | Число от 0 до 10; принимаются `7.5` и `7,5` |
| `impact` | Описание влияния, максимум 5000 символов |
| `sla_days` | Целое число от 1 до 36500 |
| `due_date` | Дата; имеет приоритет над `sla_days` |
| `linked_object_name` | Точное имя объекта без учёта регистра |
| `linked_object_ip` | IP существующего объекта |
| `linked_object_external_id` | В Sprint 11 не используется для поиска и создаёт warning |
| `owner_email` | Проверяется, но не назначает владельца автоматически |
| `external_id` | Alias для `source_record_id` |
| Source columns | Поля из раздела Source Metadata |

Поддерживаемые категории:

`vulnerability`, `configuration`, `access`, `network`, `compliance`, `incident`, `monitoring`, `organizational`, `physical`, `human`, `other`.

### Пример

```csv
title,severity,category,status,probability,cvss_score,sla_days,linked_object_name
Critical CVE on database server,critical,vulnerability,open,high,9.8,7,srv-db-01
```

### Как Находится Объект Для Связи

Поиск выполняется только внутри текущей организации:

1. По точному `linked_object_name` без учёта регистра.
2. По уникальному `linked_object_ip`.
3. Если имя и IP указывают на разные объекты, строка получает error.
4. Если объект не найден или совпадение неоднозначно, строка получает warning, а риск создаётся без связи.

Рекомендуется сначала импортировать объекты, проверить их, а затем импортировать риски с `linked_object_name`.

## Пошаговый Сценарий

### 1. Откройте Нужный Раздел

- объекты: `/objects`;
- риски: `/risks`.

### 2. Нажмите «Импорт»

Если кнопки нет, текущая роль не имеет права на выбранный тип импорта.

### 3. Укажите Источник

Заполните source name/type, confidence, дату сбора и комментарий. Эти значения применятся ко всем строкам, где файл не задаёт собственные source-поля.

### 4. Выберите Файл

Нажмите область выбора и укажите CSV или XLSX. Browser читает файл локально, затем отправляет табличную матрицу в Server Action для нормализации и повторной проверки.

### 5. Проверьте Preview

Preview не создаёт записи. Он показывает:

| Метрика | Значение |
|---|---|
| Строк | Все непустые строки данных |
| Валидных | Строки без blocking errors |
| К созданию | Валидные строки без найденных дублей |
| С ошибками | Строки, которые не будут созданы |
| Дублей | Строки, пропускаемые create-only стратегией |
| Предупреждений | Неблокирующие замечания |
| Информация | Сопоставленные и безопасно пропущенные служебные колонки |

### 6. Исправьте Ошибки

Интерфейс разделяет блокирующие ошибки, предупреждения и информацию. Однотипные неизвестные или служебные колонки группируются. Команда **Отчёт CSV** скачивает полный validation report с номером строки, полем, кодом, исходным значением и рекомендацией.

Исправления выполняются в исходном CSV/XLSX. После этого выберите исправленный файл повторно.

### 7. Подтвердите Импорт

Нажмите **Импортировать N**. Server Action повторно проверит файл, source metadata, роль и организацию перед записью.

### 8. Проверьте Результат

Итоговое состояние показывает created, skipped и failed rows. Для рисков дополнительно отображаются связанные и несвязанные записи.

## Errors И Warnings

**Error** блокирует только конкретную строку. **Warning** не блокирует строку, кроме duplicate warnings: найденные дубли намеренно пропускаются create-only стратегией.

| Код | Что Означает | Что Делать |
|---|---|---|
| `missing_required_field` | Нет обязательной колонки или значения | Добавить поле и значение |
| `invalid_enum` | Значение отсутствует в допустимом enum | Использовать значение из guide/template |
| `invalid_date` | Дата не распознана | Использовать `YYYY-MM-DD`, ISO datetime или `DD.MM.YYYY` |
| `invalid_number` | CVSS/SLA не распознаны | Проверить формат и диапазон |
| `value_too_long` | Превышен лимит поля | Сократить значение |
| `rbac_denied` | Роль не может импортировать строку | Использовать разрешённый тип или обратиться к owner |
| `object_not_found` | Объект для риска не найден | Исправить имя/IP либо связать риск вручную позже |
| `duplicate_in_file` | Похожая строка уже есть в файле | Удалить повтор |
| `possible_duplicate_existing` | Запись уже похожа на существующую | Проверить существующую модель; строка будет пропущена |
| `unknown_columns` | Несколько колонок не используются | Сверить заголовки с шаблоном; перечисленные колонки не записываются |
| `ignored_columns` | Служебные/export колонки безопасно пропущены | Действие не требуется |
| `mapped_columns` | Локализованные/export заголовки сопоставлены | Проверить информационное резюме mapping |
| `multiple_object_references` | В Risk Export несколько связанных объектов | Автоматически используется первый объект |
| `unsupported_mapping` | Поле корректно, но mapping ещё не реализован | Назначить значение вручную после импорта |

## Дубли И Partial Success

Sprint 11 использует create-only стратегию:

- существующие записи не обновляются;
- автоматический merge не выполняется;
- строки с error пропускаются;
- найденные дубли пропускаются;
- остальные валидные строки создаются;
- ошибка записи одной строки не отменяет уже созданные строки.

Объекты сравниваются консервативно по `name + type` и уникальному IP. Риски сравниваются по `title + category + severity` и по `title + linked object`. Preview прямо указывает, какой matching key сработал.

Полный rollback всего файла и массовое обновление существующих записей в Sprint 11 не поддерживаются.

## Что Происходит После Импорта

### Объекты

- создаются новые объекты;
- создаются Trust Passports;
- обновляется индекс организации;
- обновляются Objects, Dashboard и Trust Graph.

### Риски

- создаются риски и найденные связи `risk-object`;
- Trust Score каждого уникального связанного объекта пересчитывается один раз;
- обновляются Risk Registry, Objects, Dashboard, Graph и Trust Passport;
- риск без найденного объекта остаётся в реестре без влияния на объект до ручной привязки.

### Audit Log

Commit создаёт одно из событий:

- `import.objects_completed`;
- `import.risks_completed`;
- `import.failed`.

Owner и admin видят событие, инициатора и агрегированные счётчики в `/settings` → «Журнал аудита». Содержимое строк, IP, CVSS, описания и source record IDs в audit metadata не записываются.

## Ограничения Sprint 11

- импорт создаёт данные, но не обновляет существующие записи;
- используется только первый лист XLSX;
- background queue и scheduled import отсутствуют;
- прямые коннекторы к AD, SIEM, VM, CMDB и другим системам не входят в Sprint 11;
- `owner_email` не назначает владельца автоматически;
- `linked_object_external_id` не связывает риск с объектом;
- один импортируемый риск может автоматически связаться только с одним найденным объектом;
- source context хранится в текстовом блоке до появления Evidence Layer;
- общий transactional rollback файла отсутствует.

---

## Время Выполнения И Timeout

- preview до 10 секунд считается нормальным baseline для тестовых наборов Sprint 11;
- 10–30 секунд означает медленную операцию и требует проверки Network/Supabase;
- чтение файла или preview дольше 30 секунд завершается понятной ошибкой и позволяет выбрать файл повторно;
- commit имеет предел ожидания 120 секунд;
- после commit timeout нельзя запускать тот же файл повторно вслепую: сначала обновите страницу и проверьте созданные записи.

## Быстрая Диагностика

| Симптом | Проверка |
|---|---|
| Нет кнопки «Импорт» | Проверьте роль пользователя |
| Файл не выбирается | Проверьте расширение `.csv`/`.xlsx` и размер до 5 МБ |
| Нет строки заголовков | Первая непустая строка должна содержать колонки |
| «К созданию: 0» | Проверьте errors и duplicates, скачайте «Отчёт CSV» |
| Риск создан без объекта | Проверьте точное имя или уникальный IP объекта |
| Дата не распознана | Используйте ISO или `DD.MM.YYYY` |
| CSV открылся одной колонкой | Используйте delimiter comma, semicolon или tab и проверьте кавычки в заголовке |
| Выбран файл другого модуля | Используйте предложенную кнопку перехода к правильному импорту |
| Собственный Risk CSV export | Загружайте только в «Импорт рисков»; localized и `*_key` headers сопоставляются автоматически |
| Импорт завершился частично | Скачайте/проверьте failures, исправьте только пропущенные строки |
| Чтение или preview длится больше 30 секунд | Проверьте файл, сеть/Supabase и повторно выберите файл после timeout error |
| Commit длится больше 120 секунд | Обновите страницу и проверьте результат перед повторной загрузкой |
| Событие не видно в audit log | Журнал доступен только owner/admin; обновите `/settings` |

Расширенная диагностика: [TROUBLESHOOTING.md](../development/TROUBLESHOOTING.md).
