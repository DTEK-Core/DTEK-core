`Проект: DTEK Core`
`Версия: 1.0`
`Дата: 08.06.2026`
`Статус: Утверждён`
`Заменяет: PRD_Configurator.md (устарел)`
`Решение: ADR-002`

---

## 1. Назначение

Конфигуратор DTEK Core — это инструмент первичной настройки и последующей кастомизации платформы под нужды конкретной организации.

Конфигуратор решает две задачи:
1. **Быстрый старт** — помогает новой организации за несколько шагов получить готовую рабочую модель доверия.
2. **Кастомизация** — позволяет адаптировать модель доверия под специфику отрасли и организации.

---

## 2. Структура Конфигуратора

Конфигуратор состоит из двух независимых фаз:

```
Фаза 1: Мастер первичной настройки
    ↓ (выполняется один раз при создании организации)

Фаза 2: Настройки модели доверия
    ↓ (доступна постоянно в разделе "Конфигуратор")
```

---

## 3. Фаза 1 — Мастер первичной настройки

### 3.1 Назначение

Мастер запускается автоматически сразу после создания организации и проводит пользователя через серию шагов. По завершении система создаёт базовую цифровую модель, с которой можно работать немедленно.

**Цели мастера:**
- Снизить порог входа для новых пользователей
- Создать осмысленную стартовую структуру без ручного заполнения
- Сформировать начальный Trust Graph и базовые категории объектов

### 3.2 Шаги мастера

#### Шаг 1. Профиль организации

Пользователь вводит основные данные об организации.

**Поля:**
- Полное наименование организации *(обязательно)*
- Краткое наименование / торговая марка
- ИНН
- Отрасль *(обязательно, выбор из справочника)*
- Регион присутствия
- Количество сотрудников *(диапазон: до 50 / 50–250 / 250–1000 / 1000–5000 / 5000+)*

**Справочник отраслей:**
- Электроэнергетика
- Нефтегазовая промышленность
- Промышленное производство
- Транспорт и логистика
- Финансы и банки
- Ритейл и торговля
- Государственное управление
- Здравоохранение
- Образование
- ИТ и телеком
- Другое

#### Шаг 2. Инфраструктурный профиль

Пользователь указывает типы объектов, присутствующих в организации. Это определяет начальный набор типов в системе.

**Категории объектов (чекбоксы):**

*Инфраструктура:*
- Серверы
- Рабочие станции и ноутбуки
- Сетевое оборудование
- Мобильные устройства

*Программное обеспечение и сервисы:*
- Корпоративные приложения
- Базы данных
- Облачные сервисы

*Идентичности:*
- Учётные записи сотрудников
- Подрядчики и внешние пользователи

*Специальные объекты (требуют отдельного подтверждения):*
- АСУ ТП / промышленные контроллеры / IoT
- Транспортные средства и беспилотники
- Физические объекты

#### Шаг 3. Масштаб инфраструктуры

Пользователь указывает примерный масштаб каждой категории выбранных объектов. Используется для начальной оценки полноты модели.

**Для каждой выбранной категории:**
- Количество объектов (ввод числа или выбор диапазона)

#### Шаг 4. Предпросмотр модели

Система показывает пользователю, что будет создано автоматически:
- Перечень типов объектов
- Количество объектов-заглушек для заполнения
- Начальный граф (схема с центральным узлом "Организация")
- Рекомендуемые категории рисков для отрасли

#### Шаг 5. Активация

Пользователь подтверждает создание модели. Система выполняет:

**Автоматически создаётся:**
- Центральный узел "Организация" в графе доверия
- Типы объектов согласно выбранным категориям
- Шаблонные объекты-заглушки для заполнения (опционально, если указано количество)
- Базовая конфигурация весов факторов Trust Score (веса по умолчанию)
- Стартовый Trust Passport для организации

**По завершении:** пользователь перенаправляется в Центр управления (Dashboard).

### 3.3 Принципы мастера

- Мастер является **необязательным** — пользователь может пропустить шаги 2–4 и настроить систему вручную.
- Мастер **не создаёт интеграции** с внешними системами.
- Мастер **не сканирует** инфраструктуру автоматически.
- После завершения мастер **не доступен повторно** (кроме как через поддержку).
- Данные, введённые в мастере, **доступны для редактирования** в настройках организации.

### 3.4 Критерий готовности (Фаза 1)

Пользователь, только что создавший организацию, может за 5–10 минут пройти мастер и получить рабочую модель DTEK Core с базовой структурой, готовой для добавления реальных объектов.

## 4. Фаза 2 — Настройки модели доверия

### 4.1 Назначение

Постоянно доступный раздел в навигации платформы. Позволяет кастомизировать правила расчёта доверия под специфику организации.

Доступ: Владелец и Аналитик ИБ.

### 4.2 Состав Фазы 2 в MVP

#### Редактор весов факторов Trust Score

Позволяет изменить веса шести факторов модели Trust Score (ADR-001).

**Правила:**
- Сумма весов всех факторов должна равняться 100%
- Каждый вес — целое число от 0 до 100
- При сохранении система проверяет сумму и отклоняет изменение, если сумма ≠ 100
- Изменение весов запускает массовый пересчёт Trust Score всех объектов организации
- История изменений весов хранится

**Отображение:**
- Текущие значения с визуальными слайдерами
- Счётчик суммы в реальном времени (подсвечивается красным при ≠ 100)
- Кнопка "Сбросить к значениям по умолчанию"
- Кнопка "Применить изменения" (активна только при сумме = 100)

**Значения по умолчанию:**

| Фактор | Вес (%) |
|---|---|
| Уязвимости | 22 |
| Конфигурация | 18 |
| Доступы | 18 |
| Сегментация | 14 |
| Соответствие требованиям | 16 |
| Инциденты | 12 |

### 4.3 Функции вне MVP (Фаза 2, версия 2.0+)

Следующие функции запланированы для Конфигуратора в версии 2.0, но **не включаются в MVP**:

**Коннекторы источников данных**
- Active Directory / LDAP
- Сканер уязвимостей (MaxPatrol, OpenVAS, СКАНЕР ВС)
- CMDB / Системы инвентаризации
- SIEM (события безопасности)
- Облачные провайдеры (Yandex Cloud, SberCloud)
- Причина исключения: интеграции требуют агентской архитектуры и значительных ресурсов (MVP_Scope.md)

**Редактор правил оценки (Rule Engine)**
- Создание условий IF [условие] THEN [действие]
- Пример: "Если объект критичен И открыт внешний порт, снизить доверие до 'Низкого'"
- Причина исключения: требует отдельного слоя бизнес-логики, усложняет MVP

**Отраслевые конфигурации**
- Готовые профили весов для отраслей (Энергетика, Финансы, Госсектор)
- Причина исключения: требует экспертной настройки под каждую отрасль

### 4.4 Критерий готовности (Фаза 2)

Пользователь (Владелец или Аналитик ИБ) может изменить веса факторов Trust Score, убедиться что сумма равна 100%, сохранить настройки и увидеть пересчитанные оценки объектов.

## 6. UX-принципы Конфигуратора

- **Мастер — линейный.** Шаги идут последовательно, возврат назад доступен, пропуск вперёд — нет.
- **Обязательные поля минимальны.** Только то, без чего модель не может быть создана.
- **Предпросмотр до активации.** Пользователь видит, что будет создано, до подтверждения.
- **Настройки модели — немедленный эффект.** Изменение весов перерассчитывает оценки без задержки.
- **Деструктивные действия подтверждаются.** Сброс весов к умолчаниям требует подтверждения.
