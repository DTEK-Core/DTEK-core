`Решение: ADR-001`

---

## 1. Назначение

Trust Score — числовая оценка уровня доверия к объекту организации в диапазоне от 0 до 100.

Оценка рассчитывается автоматически по взвешенной мультифакторной модели на основе данных, доступных в системе: рисков, характеристик объекта и полноты его цифрового паспорта.

**Trust Score используется для:**
- единой оценки состояния каждого объекта;
- приоритизации работы с рисками;
- формирования индекса доверия всей организации;
- принятия управленческих решений на основе данных;
- визуализации состояния инфраструктуры в реальном времени.

---

## 2. Уровни доверия

| Диапазон | Уровень | Цвет | Ключ |
|---|---|---|---|
| 80 – 100 | Высокое доверие | Бирюзовый | `high` |
| 60 – 79 | Достаточное доверие | Зелёный | `good` |
| 40 – 59 | Среднее доверие | Жёлтый | `medium` |
| 20 – 39 | Низкое доверие | Оранжевый | `low` |
| 0 – 19 | Критическое состояние | Красный | `critical` |

Уровень отображается в Trust Passport, карточке объекта, графе доверия и дашборде организации.

## 3. Мультифакторная модель

### 3.1 Формула

```
Trust Score = Σ (factor_score_i × weight_i) / 100
Trust Score = clamp(Trust Score, 0, 100)
```

Trust Score является взвешенной суммой оценок шести независимых факторов. Каждый фактор имеет вес от 0 до 100, сумма весов равна 100.

### 3.2 Факторы и веса по умолчанию

| № | Фактор | Ключ | Вес (%) | Описание |
|---|---|---|---|---|
| 1 | Уязвимости | `vuln` | 22 | CVE, устаревшие компоненты, поверхность атаки |
| 2 | Конфигурация | `config` | 18 | Соответствие эталонным конфигурациям, хардненинг |
| 3 | Доступы | `access` | 18 | Избыточные права, MFA, ротация учётных данных |
| 4 | Сегментация | `network` | 14 | Сетевая изоляция, открытые порты, внешняя экспозиция |
| 5 | Соответствие требованиям | `compliance` | 16 | Покрытие политиками ИБ и регуляторными требованиями |
| 6 | Инциденты | `incident` | 12 | Зафиксированные аномалии, инциденты и их давность |
| | **Итого** | | **100** | |

Веса факторов являются настройками организации и могут быть изменены через Конфигуратор. Сумма весов обязана равняться 100.

### 3.3 Базовое значение фактора

Каждый фактор начинается с базового значения, определяемого критичностью объекта:

| Критичность объекта | Базовое значение фактора |
|---|---|
| Low (низкая) | 80 |
| Medium (средняя) | 75 |
| High (высокая) | 70 |
| Critical (критичная) | 65 |

**Обоснование:** Критичный объект изначально несёт больший риск для организации — это отражается в стартовом значении. Даже при отсутствии зафиксированных рисков критичный объект не получает максимальную оценку без подтверждённых данных.

## 4. Расчёт оценки фактора в MVP

### 4.1 Источник данных в MVP

В MVP (без коннекторов к внешним системам) каждый фактор рассчитывается из вручную введённых рисков, привязанных к объекту. Риски влияют на факторы через категорию.

### 4.2 Соответствие категорий рисков факторам

| Категория риска | Влияет на фактор |
|---|---|
| `vulnerability` — Уязвимость | `vuln` |
| `configuration` — Конфигурация | `config` |
| `access` — Доступы | `access` |
| `network` — Сетевая изоляция | `network` |
| `compliance` — Соответствие | `compliance` |
| `incident` — Инцидент | `incident` |
| `monitoring` — Мониторинг | `incident` |
| `organizational`, `physical`, `human` | Все факторы равномерно (÷ 6) |

Если категория риска не указана — риск равномерно снижает все шесть факторов.

### 4.3 Штрафы за риски

| Критичность риска | Штраф к фактору |
|---|---|
| Low | −5 |
| Medium | −15 |
| High | −25 |
| Critical | −40 |

Учитываются только риски в статусе `open` или `in_progress`. Риски в статусе `accepted`, `mitigated`, `closed` не влияют на оценку.

### 4.4 Бонус за полноту данных (фактор Compliance)

Фактор `compliance` получает дополнительный бонус за заполненность цифрового паспорта объекта:

| Полнота паспорта | Бонус к фактору compliance |
|---|---|
| ≥ 80% | +10 |
| ≥ 95% | +20 |

**Расчёт полноты паспорта:**

| Поле объекта | Вес в полноте |
|---|---|
| Название | 15% |
| Тип | 10% |
| Владелец | 10% |
| Критичность | 10% |
| Описание | 15% |
| IP-адрес / сетевой идентификатор | 10% |
| Платформа / ОС | 10% |
| Сетевой сегмент | 10% |
| Тип экспозиции | 10% |
| **Итого** | **100%** |

### 4.5 Алгоритм расчёта одного фактора

```
base = criticality_base[object.criticality]          // 65–80

risk_penalty = Σ penalty[risk.severity]
               для всех рисков с matching category
               и статусом open/in_progress

completeness_bonus = 0
если factor == 'compliance':
    если completeness >= 95%: completeness_bonus = 20
    иначе если completeness >= 80%: completeness_bonus = 10

factor_score = clamp(base - risk_penalty + completeness_bonus, 0, 100)
```

### 4.6 Итоговый расчёт Trust Score

```
trust_score = round(
    Σ (factor_score_i × weight_i) / 100
)
trust_score = clamp(trust_score, 0, 100)
```

## 5. Пример расчёта

**Объект:** Сервер, критичность: High, базовое значение факторов: 70

**Риски объекта:**
- Уязвимость, High → штраф -25 к фактору `vuln`
- Конфигурация, Medium → штраф -15 к фактору `config`

**Полнота паспорта:** 85% → бонус +10 к фактору `compliance`

**Расчёт факторов (веса по умолчанию):**

| Фактор | Вес | Base | Штраф | Бонус | Оценка | Вклад |
|---|---|---|---|---|---|---|
| `vuln` | 22% | 70 | −25 | 0 | 45 | 9.9 |
| `config` | 18% | 70 | −15 | 0 | 55 | 9.9 |
| `access` | 18% | 70 | 0 | 0 | 70 | 12.6 |
| `network` | 14% | 70 | 0 | 0 | 70 | 9.8 |
| `compliance` | 16% | 70 | 0 | +10 | 80 | 12.8 |
| `incident` | 12% | 70 | 0 | 0 | 70 | 8.4 |
| **Trust Score** | | | | | | **63.4 → 63** |

**Уровень доверия: Достаточное (60–79)**

## 6. Организационный индекс доверия

Индекс доверия организации (Organization Trust Index) рассчитывается как среднее взвешенное Trust Score всех активных (не архивных) объектов:

```
org_trust_score = round(
    Σ (object.trust_score × criticality_weight) /
    Σ criticality_weight
)
```

Критичность объекта влияет на его вклад в общий индекс:

| Критичность | Вес в индексе |
|---|---|
| Critical | 4 |
| High | 3 |
| Medium | 2 |
| Low | 1 |

Критичные объекты с низким доверием оказывают наибольшее влияние на индекс организации.

---

## 7. Пересчёт Trust Score

Trust Score объекта пересчитывается автоматически при наступлении следующих событий:

| Событие | Триггер |
|---|---|
| Изменение полей объекта | `objects.updated_at` |
| Добавление риска к объекту | INSERT в `object_risks` |
| Изменение статуса/критичности риска | UPDATE `risks.status`, `risks.severity` |
| Удаление связи риска с объектом | DELETE из `object_risks` |
| Изменение весов факторов организации | UPDATE `trust_factor_config` |
| Ручной запрос переоценки | Кнопка "Переоценить" в UI |

Пересчёт выполняется через Supabase Edge Function, вызываемую Database Trigger.

---

## 8. История изменений Trust Score

Система хранит полную историю изменений Trust Score для каждого объекта.

**Для каждой записи истории хранится:**
- Дата и время изменения
- Предыдущее значение
- Новое значение
- Изменение по факторам (JSON)
- Причина изменения (текст)
- Источник: `system` (автоматический пересчёт) или `user:{id}` (ручной запрос)

## 9. Будущее развитие (v2+)

В последующих версиях каждый фактор получит собственный источник данных:

| Фактор | Источник данных (v2+) |
|---|---|
| `vuln` | Коннектор к сканеру уязвимостей (OpenVAS, СКАНЕР ВС, MaxPatrol) |
| `config` | CMDB, коннектор к эталонным конфигурациям |
| `access` | Active Directory, PAM-система |
| `network` | Сканер сети, NetFlow, firewall-политики |
| `compliance` | Коннектор к GRC-системе, автоматические чеклисты |
| `incident` | SIEM (коннектор к событиям ИБ) |

При подключении коннектора фактор переключается с ручного расчёта (риски) на автоматический (данные из системы), не затрагивая остальные факторы и не требуя изменений в формуле.

---

## 10. Принципы работы с моделью

- Trust Score является оценочным показателем, а не абсолютной истиной.
- При отсутствии данных по фактору используется нейтральное значение 70 (не максимальное).
- Минимальное значение Trust Score: 0. Максимальное: 100.
- Округление до целого числа применяется только к итоговому результату.
- Факторные оценки хранятся с точностью до целого числа.
