# User Stories — DTEK Core MVP

`Проект: DTEK Core`
`Версия: 1.0`
`Дата: 08.06.2026`
`Статус: Утверждён`

---

## О документе

Пользовательские истории (User Stories) описывают функциональность MVP с точки зрения конечного пользователя. Каждая история сформулирована по шаблону:

> **Как** [роль пользователя],  
> **я хочу** [выполнить действие],  
> **чтобы** [получить ценность / достичь цели].

История считается реализованной, когда все Acceptance Criteria выполнены.

**Роли:** Владелец (owner) · Аналитик ИБ (analyst) · Администратор (admin) · Наблюдатель (viewer)

---

## EPIC 1 — Аутентификация

### US-001: Регистрация нового аккаунта

**Как** новый пользователь,  
**я хочу** зарегистрироваться на платформе по email и паролю,  
**чтобы** получить доступ к DTEK Core и создать цифровую модель своей организации.

**Acceptance Criteria:**
- [ ] Форма регистрации принимает: имя, фамилию, email, пароль
- [ ] Пароль требует минимум 8 символов
- [ ] После отправки формы на email приходит письмо с подтверждением
- [ ] До подтверждения email вход в систему невозможен
- [ ] При попытке зарегистрироваться с уже существующим email отображается понятное сообщение об ошибке
- [ ] После успешного подтверждения пользователь перенаправляется на страницу создания организации

---

### US-002: Вход в систему

**Как** зарегистрированный пользователь,  
**я хочу** войти в платформу по email и паролю,  
**чтобы** получить доступ к данным своей организации.

**Acceptance Criteria:**
- [ ] Форма входа принимает email и пароль
- [ ] При неверных учётных данных отображается сообщение об ошибке (без указания, что именно неверно — email или пароль)
- [ ] При успешном входе пользователь перенаправляется на Dashboard
- [ ] Сессия сохраняется при закрытии вкладки браузера (при включённом "Запомнить меня")
- [ ] Заблокированный пользователь не может войти в систему и видит соответствующее сообщение

---

### US-003: Выход из системы

**Как** авторизованный пользователь,  
**я хочу** выйти из платформы,  
**чтобы** защитить свои данные при работе с общим устройством.

**Acceptance Criteria:**
- [ ] Кнопка выхода доступна из меню профиля
- [ ] После выхода сессия уничтожается (refresh token аннулируется)
- [ ] После выхода пользователь перенаправляется на страницу входа
- [ ] Обращение к защищённым страницам после выхода перенаправляет на вход

---

### US-004: Сброс пароля

**Как** пользователь, забывший пароль,  
**я хочу** сбросить пароль через email,  
**чтобы** восстановить доступ к аккаунту.

**Acceptance Criteria:**
- [ ] Ссылка "Забыли пароль?" доступна на странице входа
- [ ] Пользователь вводит email — система отправляет письмо со ссылкой сброса
- [ ] Ссылка действительна 1 час
- [ ] После перехода по ссылке пользователь вводит новый пароль (с подтверждением)
- [ ] После успешного сброса пользователь перенаправляется на страницу входа
- [ ] Если email не найден — сообщение не раскрывает факт существования аккаунта

---

## EPIC 2 — Организации

### US-010: Создание организации

**Как** авторизованный пользователь без организации,  
**я хочу** создать организацию на платформе,  
**чтобы** начать строить цифровую модель доверия своей компании.

**Acceptance Criteria:**
- [ ] При первом входе (нет организации) пользователь видит экран создания организации
- [ ] Форма принимает: название, краткое название, описание, отрасль
- [ ] После создания организации запускается Мастер первичной настройки (Configurator Phase 1)
- [ ] Создавший пользователь автоматически получает роль Владелец
- [ ] Автоматически создаётся запись `trust_factor_config` с весами по умолчанию
- [ ] Автоматически создаётся центральный узел организации в графе

---

### US-011: Просмотр профиля организации

**Как** участник организации (любая роль),  
**я хочу** видеть основную информацию об организации,  
**чтобы** понимать контекст цифровой модели.

**Acceptance Criteria:**
- [ ] На странице организации отображаются: название, отрасль, регион, размер, ИНН, дата создания
- [ ] Отображается текущий индекс доверия организации с цветовой индикацией
- [ ] Отображается статистика: количество объектов, участников, открытых рисков

---

### US-012: Редактирование профиля организации

**Как** Владелец организации,  
**я хочу** редактировать данные организации,  
**чтобы** поддерживать актуальность информации.

**Acceptance Criteria:**
- [ ] Форма редактирования доступна только Владельцу
- [ ] Все поля организации доступны для изменения
- [ ] Изменения сохраняются немедленно с подтверждением успеха
- [ ] Остальные участники видят обновлённые данные без перезагрузки страницы

---

### US-013: Работа с несколькими организациями

**Как** пользователь, являющийся участником нескольких организаций,  
**я хочу** переключаться между организациями,  
**чтобы** управлять их моделями доверия из одного аккаунта.

**Acceptance Criteria:**
- [ ] Список доступных организаций отображается в навигации
- [ ] Для каждой организации отображается роль пользователя и индекс доверия
- [ ] Переключение между организациями происходит без повторной авторизации
- [ ] Активная организация выделена визуально

---

## EPIC 3 — Управление пользователями

### US-020: Просмотр списка участников

**Как** Владелец организации,  
**я хочу** видеть всех участников организации,  
**чтобы** контролировать доступ к данным.

**Acceptance Criteria:**
- [ ] Таблица участников показывает: имя, email, роль, команду, статус, последнюю активность
- [ ] Доступна сортировка по имени, роли, статусу
- [ ] Заблокированные и ожидающие приглашения участники выделены визуально
- [ ] Страница доступна только Владельцу

---

### US-021: Приглашение пользователя

**Как** Владелец организации,  
**я хочу** создать приглашение для нового участника,<br>
**чтобы** предоставить ему доступ к цифровой модели.

**Acceptance Criteria:**
- [ ] Форма приглашения принимает: email, роль (analyst / admin / viewer)
- [ ] После создания показаны email, роль и manual invite link
- [ ] Ссылку можно скопировать и передать адресату вручную
- [ ] В списке участников появляется запись со статусом "Приглашён"
- [ ] Приглашение действительно 7 дней
- [ ] Нельзя пригласить email, который уже является участником организации
- [ ] Нельзя пригласить с ролью Владелец

---

### US-022: Принятие приглашения

**Как** приглашённый пользователь,  
**я хочу** принять приглашение и получить доступ к организации,  
**чтобы** начать работу на платформе.

**Acceptance Criteria:**
- [ ] Manual invite link ведёт на страницу принятия без предварительной сессии
- [ ] Если у пользователя нет аккаунта — предлагается регистрация
- [ ] Если аккаунт есть — предлагается вход
- [ ] После принятия пользователь добавляется в организацию с указанной ролью
- [ ] При истёкшем приглашении отображается понятное сообщение
- [ ] Пользователь перенаправляется на Dashboard организации

---

### US-023: Изменение роли участника

**Как** Владелец организации,  
**я хочу** изменить роль участника,  
**чтобы** скорректировать его уровень доступа.

**Acceptance Criteria:**
- [ ] Роль участника изменяется через выпадающий список или модальное окно
- [ ] Роль Владельца нельзя снять с последнего Владельца
- [ ] Нельзя повысить пользователя до роли Владелец через этот интерфейс
- [ ] Изменение роли применяется немедленно

---

### US-024: Блокировка участника

**Как** Владелец организации,  
**я хочу** заблокировать участника,  
**чтобы** немедленно ограничить его доступ при необходимости.

**Acceptance Criteria:**
- [ ] Заблокированный пользователь не может войти в систему
- [ ] Активные сессии заблокированного пользователя аннулируются
- [ ] Блокировка не удаляет данные пользователя
- [ ] Действие требует подтверждения
- [ ] Владелец не может заблокировать себя

---

### US-025: Удаление участника

**Как** Владелец организации,  
**я хочу** удалить участника из организации,  
**чтобы** полностью отозвать его доступ.

**Acceptance Criteria:**
- [ ] Удаление требует подтверждения с предупреждением о последствиях
- [ ] После удаления пользователь теряет доступ ко всем данным организации
- [ ] Объекты и риски, созданные удалённым пользователем, сохраняются (owner_id = NULL)
- [ ] Нельзя удалить последнего Владельца организации

---

## EPIC 4 — Управление объектами

### US-030: Просмотр списка объектов

**Как** участник организации (любая роль),  
**я хочу** видеть все объекты цифровой модели,  
**чтобы** понимать состав инфраструктуры и уровень доверия каждого объекта.

**Acceptance Criteria:**
- [ ] Таблица показывает: название, тип, сегмент, критичность, количество рисков, Trust Score, время обновления
- [ ] Доступна сортировка по названию, Trust Score, количеству рисков
- [ ] Доступна фильтрация по типу объекта и уровню доверия
- [ ] Доступен поиск по названию и ID
- [ ] Доступно переключение между табличным и карточным видом
- [ ] Объекты в статусе "Архивирован" скрыты по умолчанию (фильтром)

---

### US-031: Создание объекта

**Как** Аналитик ИБ,  
**я хочу** создать новый объект в цифровой модели,  
**чтобы** отразить реальный актив организации в системе.

**Acceptance Criteria:**
- [ ] Форма создания принимает: название, тип, описание, владельца, критичность, IP-адрес, платформу, сегмент, экспозицию
- [ ] Поля "Название" и "Тип" обязательны
- [ ] После создания автоматически создаётся Trust Passport
- [ ] Trust Score устанавливается в начальное значение согласно модели (зависит от критичности)
- [ ] Объект появляется в списке и в графе доверия
- [ ] Администратор может создавать только инфраструктурные типы объектов

---

### US-032: Редактирование объекта

**Как** Аналитик ИБ,  
**я хочу** редактировать данные объекта,  
**чтобы** поддерживать актуальность цифровой модели.

**Acceptance Criteria:**
- [ ] Все поля объекта доступны для редактирования (кроме ID и даты создания)
- [ ] Изменение критичности запускает пересчёт Trust Score
- [ ] История изменений объекта фиксируется
- [ ] Форма редактирования доступна с экрана деталей объекта

---

### US-033: Удаление объекта

**Как** Аналитик ИБ,  
**я хочу** удалить объект из модели,  
**чтобы** убрать неактуальные данные.

**Acceptance Criteria:**
- [ ] Удаление требует явного подтверждения с информацией о последствиях
- [ ] При удалении объекта удаляются: его паспорт, привязанные связи, история Trust Score
- [ ] Риски, привязанные к объекту, не удаляются (только связь `object_risks`)
- [ ] Действие необратимо

---

### US-034: Просмотр деталей объекта

**Как** участник организации (любая роль),  
**я хочу** видеть полную информацию об объекте,  
**чтобы** оценить его состояние и риски.

**Acceptance Criteria:**
- [ ] Страница деталей содержит 5 вкладок: Обзор, Факторы доверия, Риски, Связи, История
- [ ] На вкладке "Обзор": Trust Ring, ключевые метрики, краткий список рисков, связанные объекты
- [ ] На вкладке "Факторы доверия": оценка по каждому из 6 факторов с прогрессбаром и весом
- [ ] На вкладке "Риски": список рисков объекта с критичностью и статусом
- [ ] На вкладке "Связи": список связанных объектов с Trust Score каждого
- [ ] На вкладке "История": хронологическая лента изменений

---

### US-035: Архивирование объекта

**Как** Аналитик ИБ,  
**я хочу** архивировать объект,  
**чтобы** исключить его из активной модели, сохранив историю.

**Acceptance Criteria:**
- [ ] Архивированный объект не участвует в расчёте индекса доверия организации
- [ ] Архивированный объект не отображается в графе
- [ ] Паспорт архивированного объекта доступен для просмотра
- [ ] Архивирование обратимо — объект можно разархивировать

---

## EPIC 5 — Trust Passport

### US-040: Просмотр паспорта доверия

**Как** участник организации (любая роль),  
**я хочу** открыть цифровой паспорт объекта,  
**чтобы** получить исчерпывающую информацию о его уровне доверия.

**Acceptance Criteria:**
- [ ] Паспорт содержит: заголовок с названием и ID объекта, Trust Ring с числовым значением и уровнем
- [ ] Отображаются: краткая статистика (изменение за 30 дней, открытые риски, связи, покрытие политиками)
- [ ] Отображается разбивка расчёта Trust Score по 6 факторам с весами и вкладами
- [ ] Отображается итоговая составная полоса (общий Trust Score как сумма вкладов)
- [ ] Отображается список рисков объекта с критичностью, ID и SLA
- [ ] Отображается блок реквизитов: тип, IP, платформа, сегмент, экспозиция, владелец
- [ ] Внизу паспорта — "печать подтверждения" с датой расчёта

---

### US-041: Понимание факторов доверия

**Как** Аналитик ИБ,  
**я хочу** видеть детальную разбивку Trust Score по факторам,  
**чтобы** понять, что именно снижает доверие к объекту.

**Acceptance Criteria:**
- [ ] Каждый из 6 факторов показывает: название, вес (%), текущую оценку, прогрессбар
- [ ] Цвет прогрессбара соответствует уровню доверия фактора
- [ ] Отображается описание, что означает данный фактор
- [ ] Вклад каждого фактора в итоговый Trust Score отображается как число

---

### US-042: История изменений паспорта

**Как** Аналитик ИБ,  
**я хочу** видеть историю изменений Trust Score объекта,  
**чтобы** понимать динамику доверия и причины изменений.

**Acceptance Criteria:**
- [ ] История отображается в хронологическом порядке (новые первые)
- [ ] Каждая запись содержит: дату, событие, изменение Trust Score (старое → новое, дельта)
- [ ] Причина изменения отображается в читаемом виде (напр. "Добавлен критический риск")

---

### US-043: Экспорт паспорта в PDF

**Как** Аналитик ИБ,  
**я хочу** скачать паспорт доверия объекта в формате PDF,  
**чтобы** предоставить его заинтересованным сторонам или сохранить для аудита.

**Acceptance Criteria:**
- [ ] Кнопка "PDF" доступна на странице паспорта
- [ ] Экспортированный PDF содержит все блоки паспорта: заголовок, оценку, факторы, риски, реквизиты
- [ ] PDF содержит дату и время генерации
- [ ] PDF содержит логотип и название платформы
- [ ] Генерация начинается немедленно при нажатии кнопки

---

## EPIC 6 — Trust Score

### US-050: Просмотр Trust Score объекта

**Как** участник организации (любая роль),  
**я хочу** видеть актуальный Trust Score объекта везде, где объект отображается,  
**чтобы** быстро оценивать состояние инфраструктуры.

**Acceptance Criteria:**
- [ ] Trust Score отображается в: списке объектов, карточке объекта, паспорте, графе, дашборде
- [ ] Trust Score отображается числом (0–100) с цветовым индикатором уровня
- [ ] На дашборде показывается агрегированный индекс доверия организации с динамикой

---

### US-051: Понимание что влияет на Trust Score

**Как** Аналитик ИБ,  
**я хочу** видеть, какие конкретные данные влияют на Trust Score объекта,  
**чтобы** знать, какие действия повысят оценку.

**Acceptance Criteria:**
- [ ] На экране деталей объекта (вкладка "Факторы") отображается разбивка по 6 факторам
- [ ] Видно, какие риски снижают какой фактор
- [ ] Приблизительный эффект от устранения риска отображается в деталях риска

---

### US-052: История Trust Score

**Как** Аналитик ИБ,  
**я хочу** видеть, как изменялся Trust Score объекта во времени,  
**чтобы** отслеживать тренд безопасности.

**Acceptance Criteria:**
- [ ] График динамики Trust Score доступен на странице деталей объекта
- [ ] Минимальный период отображения — последние 30 дней
- [ ] На графике видны ключевые события (добавление рисков, изменения настроек)

---

## EPIC 7 — Реестр рисков

### US-060: Просмотр реестра рисков

**Как** участник организации (любая роль),  
**я хочу** видеть все риски организации в едином списке,  
**чтобы** понимать общую картину угроз.

**Acceptance Criteria:**
- [ ] Таблица показывает: название, объект, категорию, статус, SLA, оценку риска
- [ ] Доступна фильтрация по критичности и статусу
- [ ] Доступен поиск по названию, объекту и ID
- [ ] Риски отсортированы по убыванию оценки по умолчанию
- [ ] Счётчики по критичности (Критические / Высокие / Средние / Низкие) кликабельны как фильтры

---

### US-061: Создание риска

**Как** Аналитик ИБ,  
**я хочу** зарегистрировать новый риск,  
**чтобы** зафиксировать угрозу в системе и отразить её влияние на Trust Score.

**Acceptance Criteria:**
- [ ] Форма принимает: название, описание, категорию, критичность, вероятность, влияние, ответственного, SLA
- [ ] Поля "Название" и "Критичность" обязательны
- [ ] После сохранения риск появляется в реестре
- [ ] Можно сразу привязать риск к объекту при создании
- [ ] Администратор не имеет права создавать риски

---

### US-062: Привязка риска к объекту

**Как** Аналитик ИБ,  
**я хочу** привязать риск к одному или нескольким объектам,  
**чтобы** корректно отразить влияние угрозы на Trust Score конкретных объектов.

**Acceptance Criteria:**
- [ ] Привязка доступна из формы создания риска и из деталей риска
- [ ] Один риск может быть привязан к нескольким объектам
- [ ] После привязки Trust Score затронутых объектов пересчитывается
- [ ] На странице объекта отображаются все его риски
- [ ] Отвязывание риска от объекта также пересчитывает Trust Score

---

### US-063: Редактирование риска

**Как** Аналитик ИБ,  
**я хочу** редактировать данные риска,  
**чтобы** актуализировать информацию об угрозе.

**Acceptance Criteria:**
- [ ] Все поля риска доступны для редактирования
- [ ] Изменение критичности немедленно пересчитывает Trust Score связанных объектов
- [ ] История изменений риска фиксируется

---

### US-064: Изменение статуса риска

**Как** Аналитик ИБ,  
**я хочу** изменять статус риска (В работе / Устранён / Принят / Закрыт),  
**чтобы** отражать прогресс работы с угрозой.

**Acceptance Criteria:**
- [ ] Изменение статуса доступно из реестра рисков и из детального просмотра
- [ ] При переводе в статус "Устранён", "Принят", "Закрыт" — риск перестаёт влиять на Trust Score
- [ ] Соответствующие объекты пересчитываются немедленно
- [ ] SLA-таймер останавливается при закрытии риска

---

### US-065: Просмотр деталей риска

**Как** участник организации (любая роль),  
**я хочу** видеть детальную информацию по риску,  
**чтобы** понять его природу, влияние и статус работы.

**Acceptance Criteria:**
- [ ] Детали отображаются в боковой панели (drawer) без перехода на новую страницу
- [ ] Показываются: оценка риска (шкала), категория, статус, владелец, возраст, SLA, влияние
- [ ] Отображается влияние на Trust Score: "устранение повысит доверие объекта на ~N пунктов"
- [ ] Отображается список рекомендуемых действий
- [ ] Кнопки быстрого действия: "Взять в работу", "Принять риск"

---

### US-066: Экспорт реестра рисков

**Как** Аналитик ИБ,  
**я хочу** экспортировать реестр рисков,  
**чтобы** передать данные для отчётности или внешнего анализа.

**Acceptance Criteria:**
- [ ] Кнопка "Экспорт" доступна на странице реестра рисков
- [ ] Экспорт доступен в формате CSV
- [ ] Экспортируются применённые фильтры (только отфильтрованные риски)
- [ ] В CSV включены все поля риска

## EPIC 8 — Граф доверия

### US-070: Просмотр графа доверия

**Как** участник организации (любая роль),  
**я хочу** видеть граф связей между объектами,  
**чтобы** понимать структуру инфраструктуры и цепочки зависимостей.

**Acceptance Criteria:**
- [ ] Граф отображает все активные объекты как узлы
- [ ] Связи между объектами отображаются как рёбра
- [ ] Цвет узла соответствует уровню доверия объекта (5 уровней)
- [ ] Размер узла отражает критичность объекта
- [ ] Граф поддерживает масштабирование колёсом мыши
- [ ] Узлы перетаскиваются мышью (drag-and-drop)
- [ ] Центральный узел организации выделен отдельно

---

### US-071: Создание связи между объектами

**Как** Аналитик ИБ,  
**я хочу** создать связь между двумя объектами,  
**чтобы** отразить реальную зависимость в цифровой модели.

**Acceptance Criteria:**
- [ ] Создание связи доступно с экрана графа и с экрана деталей объекта
- [ ] Пользователь выбирает: исходный объект, тип связи, целевой объект
- [ ] Доступные типы связей: использует, зависит от, подключён к, управляется, владеет, взаимодействует
- [ ] Нельзя создать связь объекта с самим собой
- [ ] Дублирующаяся связь (тот же источник, цель, тип) отклоняется с сообщением об ошибке
- [ ] Новая связь мгновенно появляется на графе

---

### US-072: Удаление связи

**Как** Аналитик ИБ,  
**я хочу** удалить связь между объектами,  
**чтобы** актуализировать граф при изменении инфраструктуры.

**Acceptance Criteria:**
- [ ] Удаление связи доступно из контекстного меню ребра или боковой панели объекта
- [ ] Действие требует подтверждения
- [ ] После удаления счётчик связей объектов обновляется
- [ ] Trust Score не пересчитывается при удалении связи (связи не влияют на Score в MVP)

---

### US-073: Просмотр деталей узла графа

**Как** участник организации (любая роль),  
**я хочу** кликнуть на объект в графе и увидеть его детали,  
**чтобы** не уходить с экрана графа для получения базовой информации.

**Acceptance Criteria:**
- [ ] Клик по узлу открывает боковую панель с информацией об объекте
- [ ] Панель показывает: Trust Ring, тип, сегмент, критичность, количество рисков и связей
- [ ] Из панели доступны кнопки: "Паспорт доверия", "Детали объекта"
- [ ] Выбранный узел визуально выделяется

---

### US-074: Фильтрация графа по типу объекта

**Как** Аналитик ИБ,  
**я хочу** фильтровать граф по типу объекта,  
**чтобы** сосредоточиться на конкретной части инфраструктуры.

**Acceptance Criteria:**
- [ ] Панель фильтров по типу объекта доступна на экране графа
- [ ] При выборе типа — выделяются узлы этого типа, остальные приглушаются
- [ ] Можно выбрать несколько типов одновременно
- [ ] Сброс фильтра возвращает граф в исходное состояние

## EPIC 9 — Центр управления (Dashboard)

### US-080: Просмотр индекса доверия организации

**Как** участник организации (любая роль),

**чтобы** оценить общее состояние безопасности с первого взгляда.

**Acceptance Criteria:**

- [ ] Отображается пояснение: что именно снижает индекс
- [ ] Кнопки перехода к Графу доверия и к Объектам

**Как** Аналитик ИБ,  
**я хочу** видеть ключевые числовые показатели на дашборде,  
**чтобы** быстро получать актуальную статистику без поиска по разделам.

- [ ] Каждая карточка показывает динамику (дельта за период)

### US-082: Объекты с наименьшим доверием

**Как** Аналитик ИБ,  
**я хочу** видеть на дашборде топ-5 объектов с наименьшим Trust Score,  
**чтобы** сразу знать, где требуется первоочередное внимание.

**Acceptance Criteria:**
- [ ] Список 5 объектов с наименьшим Trust Score, отсортированный по возрастанию оценки
- [ ] Для каждого: название, тип, критичность, количество рисков, Trust Score
- [ ] Клик по объекту ведёт на его паспорт доверия
- [ ] Ссылка "Все объекты" ведёт в реестр объектов

**Как** Аналитик ИБ,  
**я хочу** видеть ленту последних событий на дашборде,

**Acceptance Criteria:**
- [ ] Лента показывает последние 10–20 событий: изменения Trust Score, новые риски, изменения статусов
- [ ] Для каждого события: время, описание, ссылка на объект
- [ ] События цветово кодированы по типу (критическое / предупреждение / информация / позитивное)

**чтобы** понимать структуру рисков организации.

**Acceptance Criteria:**
- [ ] Горизонтальные полосы для 5 уровней доверия (Высокое / Достаточное / Среднее / Низкое / Критическое)
- [ ] Для каждого уровня: цветовой индикатор, диапазон значений, количество объектов, пропорциональная полоса
- [ ] Клик по уровню открывает отфильтрованный список объектов

## EPIC 10 — Конфигуратор

### US-090: Прохождение мастера первичной настройки

**Как** Владелец новой организации,  
**я хочу** пройти мастер настройки,  
**чтобы** быстро получить готовую базовую модель доверия.

**Acceptance Criteria:**
- [ ] Мастер запускается автоматически после создания организации
- [ ] Шаги: Профиль организации → Типы объектов → Масштаб → Предпросмотр → Активация
- [ ] Можно вернуться на предыдущий шаг
- [ ] Шаги 2–4 можно пропустить (кнопка "Пропустить")
- [ ] После завершения создаётся базовая структура и открывается Dashboard
- [ ] Мастер не запускается повторно при следующем входе

### US-091: Настройка весов факторов Trust Score

**Как** Аналитик ИБ,  
**я хочу** изменить веса факторов в модели Trust Score,  
**чтобы** адаптировать оценку доверия под специфику нашей организации.

**Acceptance Criteria:**
- [ ] Раздел "Конфигуратор" доступен в навигации для Владельца и Аналитика ИБ
- [ ] Отображаются все 6 факторов с текущими весами и слайдерами
- [ ] Счётчик суммы весов обновляется в реальном времени
- [ ] Кнопка "Применить" заблокирована при сумме ≠ 100
- [ ] При сумме ≠ 100 отображается предупреждение с подсказкой на сколько нужно изменить
- [ ] После сохранения изменений запускается пересчёт Trust Score всех объектов
- [ ] Уведомление информирует, что пересчёт выполнен
- [ ] Кнопка "Сбросить к умолчаниям" восстанавливает веса по умолчанию (22/18/18/14/16/12)

## EPIC 11 — Evidence-first Platform Evolution

Эти истории не заменяют реализованные MVP stories. Они описывают развитие после ADR-007 и должны раскрываться в Sprint 11–15 и последующих интеграционных Sprint.

### US-100: Evidence Import

**Как** Аналитик ИБ,  
**я хочу** загрузить объекты и риски из CSV/XLSX с указанием источника,  
**чтобы** не заполнять цифровую модель вручную с нуля.

**Acceptance Criteria:**
- [ ] Пользователь видит preview перед импортом
- [ ] Ошибки валидации показываются до создания данных
- [ ] Импортированные записи имеют source context
- [ ] Audit log фиксирует импорт и количество строк
- [ ] Tenant isolation сохраняется через RLS/RBAC

---

### US-101: Discovery Inbox

**Как** Аналитик ИБ,  
**я хочу** видеть автоматически найденные объекты, связи и риски в очереди подтверждения,  
**чтобы** контролировать качество цифровой модели.

**Acceptance Criteria:**
- [ ] Candidate показывает source и confidence
- [ ] Пользователь может подтвердить, отклонить или объединить candidate
- [ ] Low-confidence data не влияет на Trust Score без подтверждения
- [ ] Все действия логируются

---

### US-102: Source Coverage

**Как** CISO,  
**я хочу** видеть, какими источниками подтверждён объект,  
**чтобы** понимать полноту и надёжность цифрового паспорта.

**Acceptance Criteria:**
- [ ] Trust Passport показывает список источников
- [ ] Для каждого источника виден статус и last seen
- [ ] Manual overrides отделены от connector/import data
- [ ] Непокрытые критичные объекты выделяются как риск

---

### US-103: Auto Risk Candidate

**Как** Аналитик ИБ,  
**я хочу** получать предложенные риски на основе evidence,  
**чтобы** быстрее выявлять проблемы без ручного анализа всех источников.

**Acceptance Criteria:**
- [ ] Auto risk candidate показывает причину создания
- [ ] Candidate можно подтвердить, отклонить или отложить
- [ ] Подтверждённый риск становится обычным risk registry item
- [ ] Отклонённый candidate не создаёт активный риск

---

### US-104: Connector Source Setup

**Как** Владелец или Аналитик ИБ,  
**я хочу** подключить первый источник данных через Connector Framework,  
**чтобы** DTEK Core автоматически обновлял цифровую модель доверия.

**Acceptance Criteria:**
- [ ] Настройка источника выполняется server-side
- [ ] Secrets не попадают в клиент
- [ ] Sync run имеет статус, ошибки и audit event
- [ ] Данные проходят normalization и identity resolution
- [ ] Пользователь видит результат в Discovery Inbox или Trust Passport
