## Этап 1 — Анализ текущего состояния

### Что уже является сильной стороной

#### 1. Техническая архитектура — зрелая

Платформа построена на современном стеке: Next.js 15 App Router с Server Components, Supabase Cloud с RLS на уровне каждой таблицы, TypeScript strict mode без единого `any`. Это не студенческий проект — это enterprise-ready стек, который используют серьёзные продукты.

**Особенно сильные технические решения:**
- RLS на 10 таблицах с `current_org_id()` и `current_user_role()` — изоляция данных гарантирована на уровне базы данных, не приложения
- Server Components везде по умолчанию — минимальный клиентский JS, быстрая загрузка
- Zod-валидация на всех Server Actions — невозможно отправить невалидные данные
- Rate limiting в middleware — базовая защита от брутфорса

#### 2. Trust Score Engine — реализован правильно

Математическая модель Trust Score (ADR-001) реализована корректно: чистые функции в `lib/trust/calculate.ts`, без побочных эффектов, без обращений к базе данных. Engine (`lib/trust/engine.ts`) — отдельный слой записи результатов. Это правильная архитектура: логика и I/O разделены.

Модель содержит нетривиальные детали: штрафы по категориям рисков, бонус за полноту паспорта, взвешенный организационный индекс с учётом критичности объектов. Это уровень продуманности, которого не хватает большинству CMDB-инструментов.

#### 3. Полнота MVP — высокая

16 маршрутов работают. Все 51 P1/P2-фича реализована. Пользователь может пройти полный цикл: регистрация → организация → команда → объекты → риски → граф → паспорта → дашборд → конфигуратор.

#### 4. Безопасность — выше среднего для MVP

Sprint 06 добавил security headers (CSP, X-Frame-Options, HSTS), rate limiting в middleware, Zod-валидацию, audit log. Это не типично для MVP-продуктов — большинство добавляет это позже. Для российского рынка ИБ особенно важно: заказчики сразу задают вопросы о безопасности самой платформы.

#### 5. Документация — неожиданно полная

9 security-документов, ADR, RBAC-матрица, полное руководство по тестированию. Для продукта на стадии MVP это нетипично и создаёт преимущество при демонстрации клиентам.

### Что сейчас недооценено

#### 1. Trust Score History уже есть в базе, но не визуализирован

Таблица `trust_score_history` создана и заполняется при каждом изменении оценки. Данные уже там. Но на странице объекта нет графика тренда — аналитик видит только текущий Score, не понимая динамику. **Это одна из самых ценных функций, которая уже реализована на 80%** — нужен только UI.

#### 2. Полнота паспорта посчитана, но не отображена в списке

`completeness_pct` рассчитывается и сохраняется в `trust_passports` при каждом пересчёте. Но в списке объектов (`/objects`) пользователь не видит, насколько заполнены паспорта. Добавить прогресс-бар — это несколько строк кода.

#### 3. Trust Graph не используется для анализа рисков

Граф сейчас — красивая визуализация связей. Но он не показывает: «Если этот объект скомпрометирован, сколько других объектов пострадает?» Эта информация уже есть в таблице `relations` — нужно только агрегировать.

#### 4. Dashboard событийная лента

Если в платформе реализован `notify_trigger` (миграция 014), события генерируются. Но насколько лента Dashboard полезна для аналитика — зависит от UI. Лента событий должна быть «живой»: новый риск, изменение статуса, пересчёт Score.

---

### Небольшие улучшения с большим эффектом

1. **Trend chart на странице объекта** — данные есть, нужен chart-компонент
2. **Completeness badge в списке объектов** — одна строка CSS + один query
3. **Risk count badge на объекте** — сколько открытых рисков, видно сразу
4. **Подсветка просроченных SLA** — красный цвет для рисков с due_date < today
5. **Категориальный прогресс в Risk Drawer** — «устранение этого риска даст +N к Trust Score»

## Этап 2 — Предложение Mini Sprint

### Mini Sprint: «Аналитика доверия» (Trust Analytics)

**Обоснование:** Все данные для аналитики уже существуют в базе данных. Trust Score history — есть. Completeness — есть. Risk count — есть. Нужен только UI, который сделает эти данные видимыми.

**Цель:** Превратить DTEK Core из «реестра данных» в «аналитический инструмент», добавив визуализацию данных, которые уже есть в системе.

**Что НЕ входит:** новые таблицы, новые миграции, изменение архитектуры, изменение дизайн-системы.

---

### Задачи Mini Sprint (оценка ~4–5 дней)

#### Задача A1 — Trust Score Trend Chart (1.5–2 дня)

**Что:** Микрографик истории Trust Score на странице объекта (`/objects/[id]`) и в Trust Passport (`/objects/[id]/passport`).

**Данные:** Уже есть в таблице `trust_score_history`. Нужно только добавить query и chart-компонент.

**Реализация:**
- Query: `SELECT new_score, reason, created_at FROM trust_score_history WHERE object_id = $1 ORDER BY created_at`
- Chart: sparkline через Recharts (уже в проекте) или простой SVG
- Показывать последние 30 событий / 90 дней (whichever is less)
- При наведении: дата + причина изменения + старый/новый Score

**Ценность:** Аналитик видит: «Trust Score упал с 74 до 47 три недели назад — именно тогда добавили critical vulnerability.» Это конкретный инсайт, которого сейчас нет.

---

#### Задача A2 — Completeness Badge в списке объектов (0.5–1 день)

**Что:** Индикатор полноты паспорта (0–100%) рядом с каждым объектом в списке `/objects`.

**Данные:** `completeness_pct` уже есть в таблице `trust_passports`. Нужен JOIN при загрузке списка.

**Реализация:**
- Добавить `trust_passports!inner(completeness_pct)` к query на `/objects`
- Визуализация: небольшой прогресс-бар или badge «85%» с цветом (красный < 50%, жёлтый 50–79%, зелёный 80%+)

**Ценность:** Аналитик сразу видит, какие объекты «неполные» и требуют заполнения данных. Сейчас это требует открывать каждый паспорт.

---

#### Задача A3 — SLA Warning в реестре рисков (1 день)

**Что:** Визуальное предупреждение для рисков, у которых `due_date` прошёл или истекает в течение 48 часов.

**Данные:** `due_date` уже есть в таблице `risks`. Логика сравнения — на клиенте.

**Реализация:**
- Badge «Просрочен» (красный) если `due_date < now()`
- Badge «Скоро» (оранжевый) если `due_date < now() + 48h`
- Фильтр «Просроченные» в реестре рисков

**Ценность:** Аналитик сразу видит риски, требующие немедленного внимания. Сейчас все риски выглядят одинаково, независимо от просроченности SLA.

---

#### Задача A4 — Risk Impact Hint в Risk Drawer (1 день)

**Что:** Подсказка в Risk Drawer: «Устранение этого риска повысит Trust Score объекта ориентировочно на N пунктов».

**Данные:** Текущий Trust Score объекта + параметры риска (категория, критичность). Расчёт — чистая функция уже в `lib/trust/calculate.ts`.

**Реализация:**
- Вызвать `calcFactorScore` дважды: с активным риском и без него
- Показать разницу: «↑ ~12 пунктов при закрытии»
- Это информационная подсказка, не гарантия (другие риски тоже влияют)

**Ценность:** Аналитик понимает, с чего начать. «Закрой этот риск — Trust Score вырастет на 15 пунктов» — конкретная инструкция к действию.

---

### Ожидаемый эффект Mini Sprint

| До Mini Sprint | После Mini Sprint |
|---|---|
| Список объектов: только Trust Score и статус | Список объектов: Trust Score + completeness + открытые риски |
| Страница объекта: Trust Score без истории | Страница объекта: Trust Score + trend chart |
| Реестр рисков: все риски выглядят одинаково | Реестр рисков: просроченные выделены, SLA-дедлайны видны |
| Risk Drawer: описание риска | Risk Drawer: описание + ожидаемое влияние на Trust Score |

**Суммарно:** Платформа выглядит более аналитической и «живой». Данные, которые уже есть, становятся видимыми.

**Оценка времени:** 4–5 дней одного разработчика.  
**Риск для архитектуры:** минимальный (только UI + read-only queries).  
**Конфликт с Product Review:** отсутствует (добавляет новые UI-элементы, не меняет существующие).

## Этап 4 — Коммерческий потенциал

### Насколько платформа похожа на коммерческий продукт

**Оценка: 7.5 / 10**

| Критерий | Оценка | Комментарий |
|---|---|---|
| Техническая зрелость | 8/10 | Production-grade стек, RLS, security headers |
| UX / Дизайн | 7/10 | Тёмная тема, teal-акцент — выглядит профессионально |
| Полнота функционала | 8/10 | Все 16 маршрутов работают, полный цикл |

| Документация | 9/10 | Редкость для MVP — превосходит конкурентов |
| Безопасность | 8/10 | RLS, RBAC, rate limiting, audit log |
| Аналитическая ценность | 6/10 | Данные есть, но не все визуализированы |

### Чего не хватает до первой демонстрации клиенту

**Обязательно:**
1. Пример заполненной организации с ~10 объектами и реальными рисками — демо-данные
2. Trust Score trend chart (данные есть) — без истории Score не «живёт»
3. Качественные empty states с CTA — на пустом аккаунте непонятно, что делать

**Желательно:**
4. PDF-экспорт Trust Passport (пункт R6 roadmap) — заказчики хотят распечатать
5. Onboarding tour — интерактивный тур по интерфейсу для нового пользователя

### Чего не хватает до первого пилотного внедрения

1. **Импорт данных** — ввод 500 объектов вручную нереалистичен. Нужен хотя бы CSV-импорт
2. **Уведомления по email** — при критическом изменении Trust Score, просроченном SLA
3. **Экспорт отчётов** — PDF Trust Passport + CSV реестра рисков (R6)
4. **Кастомизация типов объектов** — некоторые клиенты имеют специфические классификации
5. **ФСТЭК-соответствие** — требование для российских государственных организаций

### Какие функции дадут максимальную ценность заказчику

1. **Trust Score trend chart** — показывает динамику, не срез
2. **Risk Impact calculation** — «этот риск стоит вам 15 пунктов Trust Score»
3. **PDF Trust Passport** — документ для руководства/аудитора
4. **Email-уведомления при критических событиях** — проактивное управление
5. **Dashboard Executive View** — упрощённый вид для CISO/ГД без детального интерфейса

## Этап 5 — Рекомендации

### 1. Что реализовать первым после Product Review

**Приоритет 1: Mini Sprint «Аналитика доверия» (4–5 дней)**  
Trust Score trend chart + SLA warnings + completeness badge. Это использует существующие данные и драматически улучшает ощущение «живого» продукта.

**Приоритет 2: Демо-данные (1 день)**  
Скрипт (или Seed-файл), который создаёт тестовую организацию с реалистичными объектами, рисками и историей Trust Score. Без этого демонстрация начинается с пустого экрана.

### 2. Что приятно удивит первых пользователей

1. **Мгновенный пересчёт Trust Score** — после закрытия риска цифра меняется на глазах. Это «магия», которую пользователи демонстрируют коллегам
2. **Trust Graph** — аналитики ИБ редко видят интерактивную карту своей инфраструктуры. Первая реакция — «это мы?»
3. **Trust Ring в паспорте** — визуально красивый компонент, создаёт «ощущение документа»
4. **Автоматический Passport** — объект создан → паспорт уже готов, без дополнительных шагов

### 3. Что выделит DTEK Core среди конкурентов

1. **Единая числовая метрика (Trust Score)**, объясняемая бизнесу — это редкость среди российских инструментов ИБ
2. **Конфигурируемые веса факторов** — адаптация под отрасль без программирования
3. **Trust Graph** — визуальная модель зависимостей, которой нет в реестрах активов
4. **Real-time пересчёт** — не «раз в сутки», а при каждом действии
5. **Открытая модель расчёта** — аналитик понимает, почему Score именно такой

### 4. Что можно добавить без увеличения сложности

- **Закреплённые фильтры в реестре рисков** — «мои риски», «просроченные», «критические» — localStorage, без backend
- **Keyboard shortcuts** — K/J для навигации по списку, Enter для открытия — чисто frontend
- **Copy link on object** — кнопка «скопировать ссылку» на объект для отправки коллеге
- **Batch status update для рисков** — выбрать несколько → изменить статус — одна Server Action

### 5. Что перенести на после MVP

| Функция | Почему после |
|---|---|
| CSV-импорт объектов | Требует парсинг + валидацию + UX для ошибок — отдельный сложный модуль |
| Email-уведомления | Требует настройку транзакционного email-сервиса (Resend/SendGrid) |
| PDF-экспорт | R6 уже запланирован, сложность L |
| ФСТЭК-соответствие | Sprint 09 Security Deep |
| Multi-factor authentication | Post-MVP security sprint |
| Custom object types | Enterprise v2.0 |
| API для интеграций | Enterprise v2.0 |
| On-premise deployment | Enterprise Runtime v2.0 |

## Выводы

**DTEK Core v0.7.0 готов к первой демонстрации клиентам** при условии наличия демо-данных. Технически — это production-ready продукт. Функционально — покрывает ключевые пользовательские сценарии.

2. Sprint 09 Security Deep — ФСТЭК, SAST, penetration testing
3. Sprint 10 MVP Release — PDF/CSV экспорт, финальная полировка

**Срок до публичного запуска: ≈ 3 спринта** (оценка из MEMORY: 4 спринта до MVP-запуска, Sprint 07 завершён).
